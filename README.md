# 棋牌室

和朋友随时约一局的 Web 棋牌室。通过房间号或邀请链接加入，可以玩拉密、双人翻棋军棋，也可以先单人练习。手机可添加到主屏幕，在独立窗口中使用；牌桌以横屏为主。

[正式入口](https://game.sumomoli.com/) · [Agora 入口](https://agora.sumomoli.com/game/) · [设计文档](docs/design/README.md) · [参与设计](CONTRIBUTING.md)

这是持续开发的项目。仓库供朋友共同设计、维护者开发使用。公开内容包含应用代码、测试和产品设计，不包含线上用户数据、密钥或运维记录。`main` 是开发主线，线上部署独立验收；提交到 GitHub 不会自动更新正式服务。2026-10-06 本次整理包含尚未发布的聊天输入与自身消息提示修复。

- [拉密设计](docs/design/games/rummikub.md)：当前朋友规则、鬼牌、桌面与手牌操作、边界例子和验收。
- [军棋设计](docs/design/games/army-flip.md)：翻棋、碰暗棋、运旗、排雷及固定棋盘操作。
- [新游戏设计模板](docs/design/game-design-template.md)：朋友写玩法和例子，维护者补技术设计。
- [迭代经验](docs/design/lessons.md)：把之前漏掉的流程与交互变成设计检查项。

准备写 414 的朋友可以复制模板，填写前半部分，保存为 `414.md` 直接交给维护者，也可以提交到 [提案目录](docs/proposals/README.md)。无需先了解技术。维护者会核对歧义并补充后半部分；未明确的地方规则保持“待确认”，不会由 AI 默默猜定。

这份设计库从拉密和军棋的实际迭代中整理而来。它记录的不只是玩法，还包含进入与退出、角色权限、拖动与整理、反馈、保存恢复、弱网和边界验收，避免每款新游戏都重新漏掉相同的产品流程。具体协作方式见 [CONTRIBUTING.md](CONTRIBUTING.md)。

## 可以玩什么

- **拉密：2～7 人。** 默认 2～4 人使用两副数字牌和两张普通鬼牌，5～7 人使用三副数字牌和三张普通鬼牌。支持首次 30 点、桌面重组、四种鬼牌及开局前数量设置。
- **军棋：双人翻棋。** 棋子随机扣放、轮流翻开。朋友规则允许明棋碰暗棋；夺旗后需要运回大本营，工兵全灭后有最低官阶接替运输和牺牲排雷规则。
- **两款单人练习。** 拉密有基础和鬼牌课程；军棋有只使用公开棋子信息的自动对手。练习进度保存在本机浏览器，不占朋友房间，也不记账号战绩。

完整玩法见上面的各游戏设计。规则按版本保存，正在进行的旧局不会因更新被悄悄改变。接下来优先飞行棋；414 等朋友玩法明确后再设计。麻将、其他牌类和大富翁保留扩展方向，它们目前都不是可玩的实现，也不会把新文件放入仓库就自动启用。

## 房间与游戏体验

邀请、准备、房主开局、观战、暂停、退出本局、再来一局和房间清理使用共同的房间系统。等待期间可以选择玩家或观众；开局后新加入的成员自动观战。聊天、消息气泡、回合提示、分类音效及个人战绩也由共通模块提供。

拉密支持拖动单牌、整组移动、拼接与拆分、桌面整理和自由摆放手牌。桌上牌变多时尽量缩放显示全桌，并提供放大查看；横竖屏切换会按可用空间重新呈现。对手尚未确认的桌面操作作为短时预览显示，正式牌面只有在服务端确认后才保存。

新局每人回合 30 分钟：超时拉密摸牌，军棋跳过。离开页面与明确退出房间含义不同；关闭页面不会直接销毁牌局，明确退房则释放席位，进行中退房会中止本局且不记输赢，全员离开后关闭房间。暂停需要在席玩家同意，保存最多七天。

正式环境复用 Agora 统一身份，棋牌使用自己的登录客户端和服务端会话。身份按 `issuer + sub` 识别，昵称只供显示；房主、席位、回合和私有手牌仍由棋牌室判断。退出棋牌室只退出本项目。股票项目保持独立。

## 本机运行（开发者）

需要 **Node.js 22.23.2 或以上**、npm、Python 3 和 `tar`。Python 与 `tar` 用于发布包校验；Node 22 的 SQLite 接口可能显示 experimental 提示。

```bash
git clone https://github.com/SUMOMO1999/game-room.git
cd game-room
npm ci --ignore-scripts
npm start
```

打开 <http://127.0.0.1:4177/>。这是仅绑定本机的匿名开发预览，房间保存在内存，重启会失去房间。第一次预览不要复制生产 `.env.example` 到 `.env`：生产模板不会提供可用的本机登录配置。

单人练习入口为 `/practice.html` 和 `/army-practice.html`，大厅也提供选择入口。需要验证登录、席位和持久化流程时，使用隔离的虚构身份预览：

```bash
npm run preview:identity
```

打开 <http://127.0.0.1:4187/>。它不连接真实 Agora 或日历账号，本机档案、会话、席位和已确认牌局保存在 `.local/` 的加密 SQLite 中；该目录及密钥不应提交。私有手牌按当前虚构身份投影，不能把此模式当作正式认证。更多运行边界见 [开发与验证](docs/development.md)。

## 验证（开发者）

```bash
npm test
```

测试使用虚构身份、临时数据和本机端口。入口会从当前源码生成临时运行包并校验，不依赖私人发布记录，也不连接真实账号或 AWS。没有配置 Caddy 时，两项 HTTPS 代理测试会明确跳过，其余测试正常执行。

完整发布验证还需要从 [Caddy 官方发行版](https://github.com/caddyserver/caddy/releases)取得本平台二进制，并用官方校验值固定它；同时需要支持 `req -addext` 的 OpenSSL：

```bash
GAME_ROOM_TEST_CADDY=/absolute/path/to/caddy \
GAME_ROOM_TEST_CADDY_SHA256='填入本平台官方 SHA-256' \
npm run test:release
```

`test:release` 要求所有测试通过、零跳过，并在独立解包目录按锁文件安装运行依赖。它不会下载 Caddy、安装系统证书或部署服务器。若系统 OpenSSL 不支持所需参数，可通过 `OPENSSL_TEST_BINARY` 指定兼容二进制。

自动化覆盖规则、实体守恒、身份与席位隔离、HTTP/SSE、未知写入结果、持久化恢复、布局、音效触发、聊天与输入法。真实手机软键盘、声音听感、系统后台限制和多成员连续使用仍需真机验收；这些不会因单元测试通过而自动视为完成。

## 代码结构

```text
app/                 页面、交互、规则引擎、房间状态与自动测试
server/              登录 BFF、私有数据投影、持久存储、聊天与实时预览
scripts/             本机预览、测试、运行包构建、预检和备份恢复
infra/               HTTPS 代理、systemd 与云资源参考定义
docs/design/         共通设计、游戏设计与新游戏模板
docs/proposals/      朋友提交的游戏设计提案
```

核心逻辑独立于页面：规则引擎决定合法动作，房间系统决定谁可以执行，页面负责呈现与操作。服务端保存已确认状态并发送每位玩家可见的视图；浏览器的显示布局或临时预览不能替代正式结果。

## 部署与公开范围

`npm run build:release` 生成不含测试、用户数据或秘密的运行包；`npm run preflight:production` 和 `npm run start:production` 使用正式配置。生产需要 HTTPS 反代、棋牌专属客户端、稳定的服务端加密密钥、持久存储及经过验证的备份恢复。

当前正式认证实现按本项目的 Agora 契约约束提供方和身份检查端点，不是任意 OIDC 提供方即插即用的安装包。源码中的域名和 Cognito 标识是公开配置，不是登录凭据。独立部署需要设计自己的认证接入、参数和信任边界，不能复用 Agora 或日历客户端。`infra/` 是参考定义，包含收费资源，运行本机预览不需要创建它们。

本仓库暂未选择开源许可证。公开浏览源码不代表额外授予再分发许可；新增图像、音效和依赖需记录来源与使用条件。
