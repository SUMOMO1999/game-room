# 飞行棋资源：Step 0 计划与独立样板

资源草案 `fc-art-step0-v1`，2026-10-06。对应[朋友版规则建议](../design/games/flying-chess.md)及[资源阶段](../design/resource-stage.md)。状态：**独立静态样板，尚非操作验证通过或全量可交付**；玩家／用户尚未确认规则和风格。不注册游戏目录、不加入静态发布白名单、不启用线上大厅。

## 最小材料与本轮清单

2～4 人、四阵营，每人四架，最多 16 架；棋盘、飞机、骰子均可用仓库原生 SVG／代码绘制。没有独特卡牌、插画、牌背、隐藏棋子、天气、装备或商业皮肤，不需要批量生成位图。

- **`fc-board-v1` 棋盘**：一张，传统四角机库与顺时针折线环道，共 52 个编号外环格、四个起飞点、各四个机库槽、各 `H1…H6` 六个归航／终点位置；每架沿 50 个环格进入自己的归航道。颜色和坐标定义见规则；形状与方向辅助必须与拓扑一致。正常显示外环／归航／起飞标记；选中与最终落点为不同描边；最近正式落点加独立标记；暂停保留棋盘但关闭行动层。逻辑比例 1:1，绘图区 600×600，环格直径 30 单位。手机棋盘 288×288 时格径约 14.4 单位，**不能把格子当独立 44px 触摸目标**，必须配大尺寸选子列表／路线摘要或放大。
- **`fc-plane-v1` 飞机**：一个共用原创路径，红／蓝／黄／绿四种阵营框与圆／方／菱／三角标记，不以颜色区分唯一身份。每架显示阵营名及 1～4 序号；总实体 8～16，图案只需四个变体。正常有轮廓；选中加双描边；可行动在列表中用文字／外框说明；不可用淡化但保留标记；最近动作另有短线标记；完成用勾与完成数，不复用“机库停放”图形。样板单位图标 30×30，实际可选列表目标至少 44×44 CSS px；一格本方最多四架，以数量徽标加四个序号选择项表达，不把叠图当四个触摸点。
- **`fc-die-v1` 骰子**：共用方框与六种准确点阵，数字 1～6 为文字备用。正常结果固定；等待服务器时显示“掷骰中”，不能提前随机展示可被误认作已确认的结果；待选择明确显示当前保存骰面；不可操作／暂停说明原因。行动目标至少 48×48 CSS px，样板上方 44×44 仅为不可操作骰面目录，低横屏示意骰面 48×48。结果动画、轻动效与无动画状态均必须显示同一个已保存值。
- **`fc-route-v1` 路线与状态标记**：普通行走为连续路径，跳跃为带 `+4` 标签的短虚线，捷径为飞机／端点标记和连接线；起飞不渲染六步路线。四条捷径都标出跨过对面 `H3` 的位置，默认安全还是跨线攻击按已确认规则决定，不能从图片猜。选中、合法目标、最近落点和完成标记有不同描边／线型；色觉体验仍待真实用户验证。样板给出四条传统捷径与红色跳后飞路线，正式操作场景仍须逐一核对。
- **`fc-controls-v1` 操作呈现**：骰面、轮到谁、待选说明、飞机序号列表、确认／取消、放大和退出入口。四阵营图标与牌局图一致；多机同格列表至少四项。样板给 320px 竖屏和 568×240 低横屏信息排布示意；不是可点按钮或响应式页面。
- **声音**：计划复用平台短音与启声／静音控制，用于掷骰结果、移动、撞机、本人回合、错误及结束；按同一正式事件去重，复合跳飞只一次动作反馈。静音用文字／描边替代。当前 SVG 没有音频，不宣称听感或触摸启声通过；不足的音色在操作小样阶段检查后再补，不先制造大批文件。

## 来源、路径与失败备用

[样板 `flying-chess-step0.svg`](samples/flying-chess-step0.svg)由本仓库为这次设计原创绘制：基本几何、同一个飞机路径、点阵与系统文字；没有第三方图片、字体文件、遥测、脚本或外部链接依赖。[完整浏览器预览截图](samples/flying-chess-step0-preview.jpg)为 1280×1140 的原生 JPEG 截图，供无需 SVG 解码器的审阅使用；没有编辑或用截图替换矢量源。功能拓扑参考 [YMI 制造商／发行商原始棋盘图](https://www.ymimports.com/pages/how-to-play-aeroplane-chess-fei-xing-qi)，经浏览器逐格和独立复核确认 52 格、50 格入归航、六格归航及跨对面 H3；未复制其图片、品牌、图案或商业美术。绘图坐标、配色、格号与形状辅助为本项目定义，不能将本图格号说成制造商原标号。样板可随仓库公开分发；系统字体由设备提供，不分发字体。当前样板包含底色，非透明角色切图。

本轮只存放 `docs/assets/`，不会进入运行资源目录。正式实现时再拆出必要共用路径／公开资源，逐个明确游戏目录、两入口地址与静态白名单。加载或解码失败时，棋子保留“红圆 1／蓝方 2”等文字与轮廓、骰子保留数字、棋盘保留可读路线和坐标；不能用缺图框替代阵营或静默允许不知道目的地的确认。该备用目前是待实现契约，未完成运行场景验证。

公开棋盘没有暗面，当前玩家、对手与观众可使用同一图形。观众仍无行动列表或确认按钮；非成员不能读房间。没有手牌、拖影、共享摆牌预览；本机未确认路线只在本机显示，正式动画用已保存公开事件，未知恢复不补猜动作。资源公开不意味着未来骰序、内部存档或身份凭据可公开。

## 样板覆盖与核对记录

样板编号 `fc-step0-sheet-01`：大棋盘含全部 52 格编号、四阵营机库／归航／终点，选中飞机、四架同格、最近落点、四条跨盘捷径；侧栏含四阵营标记、六骰面、完成／禁用／选中状态及小屏布局。设计编号供放大审阅，手机必须即时可读的信息另放大显示，不要求玩家辨读缩成几像素的 `Cxx`。自己的待选路线只在本人示意图中出现；对手／观众示意图移除本机选择和预览。骰面二的本人例中，红1/3/4均在机库，明确灰底“机库”，只有红2能行动；蓝四架同格的选择表另外标为表示例，不能把无权操作的观众变成操作者。

静态核对已完成：SVG 可解码为 1280×1140，52 唯一环格／24 归航格／4 起飞点与文档坐标一致；四条飞线交叉对象均为对面 H3，六骰面点数准确（另有低横屏六点表示例）；四架同格用数量徽标及四项列表可辨。实际渲染查过 320×626 本人区域和 568×240 低横屏区域，骰面／阶段文字及确认／取消／放大／退出未被遮挡；这仍是固定排布示意，不能证明响应式重排。使用不同形状、中文名、序号与线型辅助，红色小字对比不足已加深；四阵营小字与各自浅底对比度约 4.95／4.54／4.55／4.58:1，色觉障碍用户实测仍待验收。矢量 XML／内部引用与文档相对链接通过，未含外部资源或脚本；独立复核与完整浏览器截图一致。

已修正的样板缺陷：初稿十字构图已替换成核对过的传统折线环道；归航／捷径不再由相似 Ludo 布局猜测；完成飞机放在本方 H6；机库序号与停机实体一致；观众图去除本人待选路线；机库飞机不能误示为骰面二的可行动项。底图逐格编号可被棋子遮住，属设计辅助；产品仍须用放大／路线摘要和大列表解决手机格子过小，不靠微小编号操作。

实际浏览器／设备的触摸、响应式安全区、聊天软键盘、旋转保留选择、声音、资源失败备用、两入口加载与服务端恢复仍**待验收**。不以静态 SVG 或模拟截图替代这些检查；Step 0“可开始完整实现”的门槛尚未通过。

当前未完成项及顺序：

1. 玩家确认三组关键规则与风格；维护者完成可操作但隔离的小样，用真实图形试选单架／四架叠机、取消、路线与确认。
2. 小样检查 320 宽竖屏、低横屏、长昵称、聊天键盘、旋转和大尺寸选择列表；手机若看不清棋盘，确认放大／路线摘要方案，不靠缩小文字塞满。
3. 检查掷骰后的固定点数、等待选择恢复、无合法行动、超时、暂停与观众入口；静音仍读懂行动，真机听感单列。
4. 样板与操作场景通过后再开始完整实现；正式资源目录与全部四阵营路径、状态、失败备用、两入口地址及发布清单齐备后才记本轮资源完整。
