## 校验与后续复用

正文和别名须为1～32个NFC Unicode码点、至多128 UTF-8字节的单行文字，别名至多8个；拒绝控制、零宽、双向控制、损坏代理、私用、默认不可见、NFC后仍单独存在的组合标记、视觉空白盲文符及HTML标记字符。也检查NFKC后的字符，阻止全角尖括号等变体绕过；可正常合成为“é”的重音保留。显示正文保留文字形态，转为NFC、修整首尾空格与连续显示空格。存储校验要求已规范化，不静默改写已有版本。

判词按 `zh-exact-v1` 做NFKC、ASCII英文小写、去Unicode空白、再去指定首尾标点，中间标点保留。正文和明确认可的别名使用同一处理。繁简不自动转换，拼音、错字、子串和泛称不自动接受。`hintLength` 始终取显示正文的NFC码点数；“熊猫”的提示2字、“大熊猫”别名3字，不改变提示。“R2-D2”的提示5字与“R2D2”别名4字也分别保留。

`validateDrawAndGuessWordbank(words,{categories,requireBaseMinimums})` 返回 `{valid,errors,stats}`。错误含代码、字段路径、当前词ID；歧义额外含另一词ID与路径，供逐行预览定位。目录来自数据，新增普通分类无需改校验主流程。对多个拟采用内容包，应将全部词条一起检查，不能各包通过就跳过组合歧义。退役词保留结构校验但不参与新局歧义；`selectReviewedDrawAndGuessWords` 排除草稿、退役、停用分类和未选择范围，仅做筛选，不做抽题。

代表集使用七类各3个基础词，共21个；最长正文（11码点）、不同长度别名、繁体认可别名、英文／数字、抽象词及近义但非同概念均有覆盖。Step 0若需要24词，另外3个须是明确虚构的朋友包样例，在独立样板内持有；它们不加入本基础种子，也不引用真人资料。

## 独立内容服务与隔离证据

后续获准推进的[独立内容服务](../../server/content/draw-and-guess-wordbank.mjs)使用真实加密存储的 `compareAndSwapMany`；身份、HTTP、房间和备份装配由各自所有者接入，不从请求正文接受可信账号键。调用者必须提供由正式登录层确认的 `{userKey,member:true,displayName}`。所有有效成员可共编公共包；私人包只有作者读取、编辑、复制和发布，房主身份不增加权限。对外包、版本和修改记录不返回内部 `ownerKey` 或操作者账号键。

数据仅归属 `wordbank-packs / wordbank-releases / wordbank-index` 三个scope，`schemaVersion=1`。分类和词条操作支持新增、改名／修改及停用／退役，词条修改保留稳定ID、递增定义版本；每批至多200操作、64 KiB，任一无效或歧义行均不保存整个批次。停用分类须确认当时受影响词数，词条退役及包停用须明确确认。公共或自己的已发布版可明确复制为新的独立公共／私人草稿，保留概念ID、改为新 `packId`，不自动发布副本；私人作者主动复制到公共包才分享该副本。

服务接口为 `create / copy / list / get / change / preview / publish / previewRestore / restore / queryRequest / ensureSeed / getRelease / retainRelease`。`change`检查 `expectedDraftRevision`；发布要求精确的 `previewHash + expectedDraftRevision + expectedPublishedHead`，重验内容后在同一事务写不可变release、包head／成功版本目录、提交回执和全局额度。物理release存在不足以采用，必须同时在包成功目录中，读取时核对目录hash和内容hash。恢复绑定当前草稿、head及旧版的 `diffHash`，只复制为更高revision的新草稿，再按正常预览发布；不覆盖伙伴未发布修改，也不回退旧发布记录。

内容请求编号使用 `base36(epochMillis)-UUID`，由 `createWordbankRequestId`（别名 `createRequestId`）生成；原意图编号和指纹在重试、切换页面或查询时保持。仅24小时内、未来最多5分钟的编号可执行。每个可信主体独立保存最近128回执，裁剪与 `prunedBefore` 水位推进同事务；水位以前或保留期外的旧编号无法确认，不能当新操作再执行。同主体同编号跨包／操作／正文复用拒绝，原始内容先按显示规范化再绑定指纹。

为跨重启守住未知结果，先持久登记有界pending意图和其逻辑额度，再一次原子提交全部业务内容。pending不包含候选release；存储故障或提交无法确认时只查询原编号，不能续写pending或换编号自动补发。成功响应丢失后查询到committed回执即可确认；已知内容校验失败保存rejected回执。即使最后剩余字节不足以保存拒绝详情，pending仍收费并保持未知，不能先归还额度或假称失败。过期／裁剪后的人工新操作需要用户重新确认，不从原head猜测是否成功。

默认上限为公共20包、每人私人10包、每包64分类，公共5000词／4 MiB、私人2000词／2 MiB、全部逻辑记录128 MiB。额度覆盖草稿、release、版本目录、修改摘要、引用、pending／失败／成功回执与quota记录自身，跨包数量和字节一起事务守卫。隔离测试可仅向下缩小上限以触发竞争，不提供自动扩容。当前head与期限内的等待局引用受保护；每次发布保留最近50版，原子回收最多50个未保护旧版本以守住底座64条事务上限。若大量引用同时过期，余下旧版本继续收费，后续有界发布再清理，不越额或一次无限删除。修改摘要最多180天且有2000条硬界限；这项界限下无法承诺180天内无限次编辑均有单独摘要。

`ensureSeed()`默认只初始化草稿；部署装配可明确调用 `ensureSeed({publishInitial:true})`，仅在未初始化且为空的公共基础包，一次事务导入560词草稿、不可变初始版1、head、quota和种子hash。初始操作者显示“系统基础词库”，来源 `system-seed`，不伪造真人账号。已有初始化标记、发布版或伙伴修改时都不覆写，也不因为后来传入true自动发布原草稿。该功能在隔离SQLite中验证，不表示本报告已对生产库调用。

`retainRelease`仅供可信房间装配调用，期限内保护具体发布版；先保护后房间采用若失败，可能留下到期自动失效的保守引用，但不能让已回收或未发布版被采用。房间仍须自己保存精确选择和冻结候选，公开题目不得携带维护用 `drawingCue`。`validateDrawAndGuessWordbankSnapshot(scope,value)`做单记录恢复校验；`validateDrawAndGuessWordbankState({packs,releases,index})`检查整组目录、head、hash、私人作者与精确逻辑额度，空的三个scope兼容原包。HTTP登录重检、房间CAS、正式备份manifest和全十三scope恢复不是这个纯服务的独立证明。

[服务专项](../../app/draw-and-guess-wordbank-service.test.mjs)首轮28项全部通过，包含真实Memory／SQLite、公共共同编辑、私人及同名身份隔离、同revision竞争、批量零部分写入、规范化幂等、发布预览过期、恢复草稿竞争、双人最后包数额度、引用保护及到期回收、系统初始化不覆盖、丢响应查询、unknown重建服务禁止补写、head失败无孤立release、硬字节限制、显式公共副本和坏恢复引用／quota拒绝。另有真正新Node进程重开同一临时加密SQLite，确认伙伴草稿、旧immutable版本和原请求回执保持。原词库11项回归同次运行，共39通过，失败／取消／跳过／待办均0。SQLite仍有Node既有experimental提示。后续房间保护与最终装配复核将服务专项增至39项，最新合跑结果见文末。

### 等待房间的旧版本保护补充

版本回收新增可信注入 `protectedReference({packId,referenceId,version,expiresAt})`，返回 `null` 或 `{expiresAt,guard:{scope:'rooms',id,expectedVersion,validUntil?}}`。只核实过期 `room-*` 引用，有效保护使用真实房间存储revision，与发布、head、额度和回执在同一个事务验证；房间在核实与提交之间改变会使整个事务失败。房间生命周期归属房间服务，内容服务只续词版本引用，不写房间、更不靠心跳续房。对尚未被正常清理的过期等待snapshot，可信房间装配可返回短期保守保护及不带期限的存储revision guard，防备份出现悬空版本。

未装配回调、核实失败或超过本次核实预算时，旧引用／旧版本保守保留并继续收费，不能把故障当成房间不存在。每次至多核实60个过期房间，并按房间guard占用缩减旧release删除量，严格守住存储64个独立key的事务界限；其余积压后续分批检查。`retainRelease`不会因另一个房间采用版本而顺手丢掉这些待核实引用。回调返回的新引用期限必须在当前时刻之后且至多8天，引用总数仍受1000条上限约束。

当时新增7项通过，覆盖Memory／SQLite真实房间记录竞争、引用续期、房间删除后回收、过期snapshot保守保护而不续房、回调缺失／错误、61个过期引用分批与真实64key事务，将服务专项增至35项。
