# 模块结构与新游戏接入

本项目在同一进程和同一套持久存储中运行各款游戏。隔离的是职责、状态和权限；无需为每款游戏复制账号系统、服务器或备份资源。

## 三个边界

**共通房间平台**管理账号到席位的关联、房主、角色、准备、暂停、离席、可信动作、聊天、历史权限和房间清理。`app/rooms.mjs` 通过注册表调用游戏能力。统一身份只确认用户是谁，不能绕过席位或手牌权限。

**各游戏模块**位于 `app/games/<gameType>/`。规则决定合法动作和结果，页面负责该游戏的棋盘、手牌、拖放和反馈。完整多人引擎虽然位于 app 目录供本机与测试导入，但不会通过静态 HTTP 公开。拉密和军棋互不导入对方模块。

**共通页面工具**位于 `app/platform/`。时钟只消费服务端期限；页面会话维护账号代际、页面代际和客户端来源，避免迟到请求回写；退出控制保留未知结果的原请求编号；音频与视口控制管理设备生命周期。工具不决定摸牌、走棋或胜负。聊天、连接、身份与 Web App 外壳继续使用各自模块。原公共样式保留级联顺序，军棋专有样式归军棋目录。

[共通设置](../app/platform/room-settings.mjs)只负责入口、原控件收纳和弹层生命周期；HTML 声明或页面显式装配传入节点 ID，没有游戏类型分支。原音效、规则、重开、房间安排和权限处理器继续拥有行为；切入另一弹窗前在捕获阶段关闭设置，销毁时解绑并归还节点。拉密／军棋的房间与练习、第三款飞行棋共享此契约；[交互测试](../app/room-settings.test.mjs)与[飞行棋页面流程](../app/flying-page-flow.test.mjs)分别验证原节点／事件、禁用权限、层切换、清理和同骰选机保持。公开模块与样式显式列白名单；低频偏好不另造房间或用户状态。

[共通聊天](../app/room-chat.mjs)继续拥有消息、草稿、确认、通知和输入生命周期。新页面使用 `roomChatMarkup()` 与 `mountRoomChat()`，不再手写一份发送区；原拉密／军棋静态骨架保持兼容。页面以 `data-chat-notice-anchor` 声明有实际尺寸的工具区，以 `data-chat-dismiss-notices` 声明继续游戏时收起临时气泡的操作区；共通层跳过隐藏／零尺寸盒子，保留原页面选择器兼容，不按游戏名推测布局。气泡清理不清未读、草稿或棋局；无成员的本机练习不装配联网聊天。发送／关闭目标至少44px；紧缩聊天框优先保留输入、发送、关闭和状态，收起次要计数。页面流程替身只证明调用，真实聊天模块、成员HTTP／SSE和实际浏览器布局另有[通知测试](../app/room-chat-alerts-ui.test.mjs)及[飞行棋平台验证](../app/flying-platform.test.mjs)。新游戏按[平台接入记录](design/platform.md#共通能力接入记录)分层验收。

旧 `app/app.mjs`、`rules.mjs`、`army-room.mjs` 等是兼容转发入口。旧页面网址、存储键、动作字段与请求指纹保持；新增代码应导入对应模块的实际实现，不依赖兼容文件组织新功能。

## 服务端适配器

[契约](../server/games/adapter-contract.mjs)要求每款游戏明确提供引擎动作、公私视图、状态校验、配置、房间摘要、超时、存档格式和历史结算，并声明等待期玩家变动、初始房间字段与默认期限策略。实现见 [拉密](../server/games/rummikub/adapter.mjs)、[军棋](../server/games/army-flip/adapter.mjs)与[飞行棋](../server/games/flying-chess/adapter.mjs)。不支持配置或某动作时返回明确拒绝；没有缺省的牌池、手牌、摸牌、得分或胜负推断。

`createGameRegistry` 可注入独立适配器，房间平台本身不按游戏名分支。旧拉密测试的 engine 注入由拉密适配器明确承接，不是所有游戏共有能力。浏览器[目录](../app/games/catalog.mjs)只含公开名字、路由、人数、提示和资源路径，不能放入状态、服务器实现或秘密配置。

[历史格式兼容](../server/room-snapshot-compat.mjs)保留旧格式读取与映射；飞行棋schema9、你画我猜schema10和414候选schema11分别由各适配器校验。旧游戏按原格式保存；不支持新格式的旧包不能作为已写新格式后的回退目标，不以清库解决兼容。浏览器重排布局不改变共享存档格式。

平台只在可信构造参数提供 `serverRandomInt`；游戏适配器在当前玩家、阶段与房间权限检查后采样。持久层把候选动作、骰面和回执一起提交，失败CAS候选不广播；提交时的期限由同事务守卫检查。游戏 `round` 代表整段回合，连续六点不增加 `round`，所以共通时钟不重置。

飞行棋的 `page-ui.mjs` 供完整练习与朋友房间共用，只消费投影和操作回调。`game-page.mjs` 复用原会话、可信席位、独立退出和聊天控制；`practice-engine.mjs` 只在本机练习中驱动公开确定性核心，公平随机或固定教学骰序均不进入朋友房间请求。练习存档使用独立键和 Web Locks 排他写入；另一标签更新时先禁操作，再明确恢复。不支持锁或无法保存时明确提示，仍可临时练习。公开 `board/routes/rules/art/presentation` 的传递依赖逐个列白名单，服务器适配器、房间状态、夹具和测试保持私有。

启用 `usesActionIntents` 的适配器可得到本人最近128条操作回执投影；回执不包含其他成员请求、正文、指纹或身份秘密。[客户端意图工具](../app/platform/room-action-intent.mjs)先保存原请求编号／正文／预期版本，响应未知时只读对账并阻止新意图；明确重试沿用原请求，不从房间版本变化推断成功。浏览器存储不可读取或不可写时禁发新操作，房间仍可显示。新页面必须复用独立的共通退出控制，不能用受游戏意图锁限制的普通动作方法作为唯一离席入口；未知结果期间退出的页面流程另验。现有两款游戏保留原有动作接口与恢复行为。

## 接入一款新游戏

1. 完成[分类设计](design/game-design-template.md)，明确规则、内容、可见信息、超时、结算和随机结果；维护者先按[技术计划模板](plans/game-implementation-plan-template.md)评审职责／依赖、接口／权限／数据、并发、真实共通接入、内容／容量、旧局恢复和回退，再做[资源Step 0](design/resource-stage.md)。朋友填写规则，维护者补技术，不能设计后直接实现。
2. 在本游戏目录实现纯规则、公开呈现和页面；为配置与公私视图实现服务端适配器并登记注册表。客户端提交意图，权威状态和随机结果由服务器决定。
3. 登记公开目录与资源；接入大厅、练习、路由和共通控制器。必须显式列入白名单，不能用递归公开目录代替检查。服务端、私有引擎、测试和夹具路径必须返回 404。
4. 实现存档校验、恢复与可信结算；需要新行为类型时补设计、规则和恢复测试，不能仅在数据里写一个尚未实现的动作名。
5. 跑规则、房间、HTTP/SSE、公私隔离、历史、备份和发布包测试，再检查实际输入、视口与资源。账号/登录/退出的生态改动另与 Agora 协调。

## 边界怎样防止退化

[第三游戏平台测试](../app/game-platform-boundary.test.mjs)保留没有牌池、手牌、棋盘或拉密分数的合成游戏，并由[真实飞行棋平台测试](../app/flying-platform.test.mjs)验证实际第三款的随机、两阶段动作、角色、期限、SQLite并发、新Node进程恢复和一次结算。[目录测试](../app/games/catalog-boundary.test.mjs)验证明确资源清单、真实 HTTP 的公开/私有边界，以及发布包排除嵌套测试和夹具。[控制器测试](../app/platform-controllers.test.mjs)验证时钟一次到期、页面旧结果失效、退出重试、音频和视口清理。原两款游戏的规则与完整流程测试继续保留。前三款的完整房间／练习页面均已接入大厅；后续游戏可读、新建和公开页面分别验收，不能由服务端注册推断前端已经接通。浏览器保存的游戏类型不能丢失或把显式未知类型降级成拉密。[页面流程测试](../app/flying-page-flow.test.mjs)验证未知动作期间退出、同身份恢复、跨身份清选择和真实 HTTP 资源闭包；[实局备份测试](../app/flying-backup.test.mjs)在独立新路径恢复六阶段而不恢复会话。

测试递归发现 `app/` 的 `.test.mjs` 文件，但不执行夹具目录。仅测试使用的 `app/test-support/runtime-source.mjs` 让页面测试读取兼容入口后的实际实现，它不进入发布包，也不对浏览器公开。结构拆分不能用删除旧断言替代兼容验证。


## 你画我猜的正式装配

第四款适配器通过显式阶段时钟和同时猜的业务前提扩展平台注册；旧三款仍严格room revision与原时钟。内容服务管理三类独立scope、共编草稿及不可变发布版本；房间只冻结最多120候选。设备画笔与有界笔画由独立canvas服务管理，提交以房间／presence／期限和canvas／额度的多记录事务守卫；未知笔迹只读恢复，不补写。具体设计、接口与开放门见[实现与发布范围](development-drawing.md)。

第四款当批完整包声明schema10及十三scope，并可读旧schema1～9与旧6／7／9scope备份；新的score/rank历史保持独立，旧牌分语义不改。首版正式flag默认关闭，合成HTTP/SSE／恢复证据不代替中央鲜度预算或真实设备。损坏原库先只读拒绝，不能由初始化修复后再声称预检通过。

本地批量身份装配由 `server/identity-batch-runtime.mjs` 在启动时显式选择，默认关闭；独立机器签名只授权固定中央检查接口，不是共享 OAuth client 或 Cookie。`CognitoProvider` 先验真实 JWT，批传输只合并网络封包，每个检查保留独立 ref 和原始触发期限，完成许可不缓存。`SessionService` 保有会话版本与条件失效权；HTTP 和 SSE 仍须在输出前核对同一会话及房间／presence 版本。存储只读多 owner guard 不写数据或续期，SQLite 忙时立即拒绝本次输出，不阻塞到普通写入超时。高频请求只合并最多30秒的闲置续期写入，每次线上核验保持；正式启用另须中央实际路由、独立公钥、准入及容量就绪。

客户端按每个已发送 entry 保有精确身份／token key 的所有权。健康在途检查可在原并发预算内使用独立 ref；已发送 ref 不吸收后来调用者。取消、期限失效或响应清理未实际结束时，该 key 阻止替代工作；其他健康请求的结束只释放自身所有权。wire 的内部同步清理通知先标记未知占用，再等待真正的 read／cancel 结束；通知异常也拒绝输出。该策略没有成功许可缓存、自动重试、期限重置或扩大资源上限。 收集窗口最多20ms；已满16个当前有效、未被未知owner阻塞的entry且传输有空槽时，可立即进入原发送准备，不延长期限或提前释放预算。未满批仍等待原窗口，实际发送再次执行完整fence及字节预留。

画布的领域服务与批量身份SSE的canvas／chat事件消费 `getGameContext(...,{includeView:false})` 的窄房间权限上下文：稳定席位、角色、游戏／题号、阶段、期限及事务守卫，不生成完整私人游戏画面。每store最多64房、每房当前存储version的小型不可变元数据只复用完整快照校验；每次仍读取并解密当前房间、读取presence、按可信主体查当前成员并检查等待后的TTL。缓存不保存身份许可、引擎、原快照或私人投影；新版本损坏／不存在不能回退旧版，默认完整view及旧接口保持。聊天成员读取复用相同的完整快照验证与小型成员元数据；profile昵称每次读取，答词屏障仍来自本次保存的游戏，不缓存题目或消息许可。批身份聊天的前后输出不再生成弃用的private view；每次fresh结束与唯一room-only重核都重滤原消息包，等待期间过期或不再保留的消息不输出。性能证据与开放条件见同一实施计划。

邀请绑定同样属于末端授权：`resolvedRoom`拒绝已退休邀请，并把本次已读的邀请存储版本交给窄／完整context。批身份HTTP／SSE与画布事务把邀请、房间、presence和会话一起作原子核对，不能因旧房间数据未变而允许房间号换绑后的旧输出。该守卫不增加I/O、scope或存档格式；异房／退休邀请拒绝旧包，已提交动作仍只读恢复。

末端输出的并发冲突归 `server/room-output-fence.mjs`：仅在同一已核实会话的原子存储守卫明确冲突时，于原身份期限内最多重读一次当前房间与presence。HTTP不重做已提交的绘画；SSE重新准备当前成员允许的输出，原笔迹仍须匹配boot／比赛／题号，成功核对后才标记为已发送。会话版本变更、第二次冲突、存储忙、取消或过期均拒绝，输出前再次检查原期限；此机制不续授权、不缓存成功许可。

共通主题归 `app/platform/game-theme.*`，只管理设备偏好、CSS颜色与材质变量，由共享设置装配；没有房间或账号权限。共通控件几何归 `app/platform/control-geometry.css`，经所有页面的 `app-shell.css` 引入并显式公开，负责普通圆角、纯叉居中和原生下拉箭头，高对比模式保留原生降级。主题背景使用 `background-color`，保留选择框的箭头图层；实际页面状态文字按明确节点映射，不能猜不存在的class。牌、阵营、飞机、画笔语义色与各游戏对象几何归原游戏。两层可从已上线三款的封闭源码独立构建发布，避免把尚未过容量门的新玩法混入正式范围。


绘画batch私有输出的正常会话续期与重登录边界：`SessionService.publicSession`只在server内部不可枚举地携带原存储版和授权lineage摘要。摘要包含saved session所有安全字段（只排除idleUntil／lastIdentityCheck），因此同主体但换token、CSRF、client、authTime、entry或activation metadata仍拒绝旧输出。最终检查先核主体及当前到期，再核摘要，只有纯idle续期版变化使用专门冲突。`prepareCurrentRoomOutput`的显式fresh回调与room只读重核合计最多一次，保持原context及最初id/userKey/issuer/sub/lineage；每次实际provider检查按独立ref与原units计数。batch SSE及canvas HTTP装配，旧HTTP/legacy不暗启；已提交领域写入不重做。新实现仍待最新冻结、完整Linux/原tar、同口径同步与正式中央容量验收，不能用历史制品通过覆盖。

## 414的阶段、生命周期与积分合同

第五款[414适配器](../server/games/poker414-2/adapter.mjs)采用可空`gameClock`：普通回合无时钟，发牌／勾叉阶段返回`{kind,id,deadlineAt}`，房间保存version3时钟。`actionDeadline`单独决定动作提交截止；`actionConcurrencyProblem`重新核对原意图，只对声明的动作或单次清窗开放严格兼容，不全局放宽revision。`commonActionProblem`显式拒绝414不支持的暂停、恢复和配置。其他四款沿用原策略；[不同机制的测试适配器](../app/game-platform-boundary.test.mjs)验证这些合同没有绑定牌池、当前玩家或414类型。

`lifecycleTransition`负责游戏取消／赔分；共通房间保存固定参赛者和终局摘要，然后依结果回准备室或结算。`recoverOnStartup`与`disconnectTimeoutMs`独立声明，普通读取和设备重连不触发启动恢复。[持久房间](../server/durable-rooms.mjs)保有启动就绪门、presence竞争守卫和每游戏CAS预算；414最多首次加两次重读，旧游戏重试策略不改。

[永久积分](../server/game-scores.mjs)管理账本、余额和版本／额度，不自行改房间；[提交器](../server/room-score-commit.mjs)组合房间、预留或终局积分变更并一次提交，提交后才广播与归档。更正生成新版本，只入差额，不覆盖原记录；战绩保存结算时余额，后续更正不改写历史画面。积分scope永久保留，旧战绩180天保留语义独立。备份对永久账本按提交次序重算余额，验证引用完整性。

当前代码可读schema1～11、写原四款格式及414的schema11，备份涵盖16scope；旧6／7／9／13scope仍能读取并明确缺少哪些内容。注册表的已知适配器与`creationTypes`分别控制恢复和新房间／新开局；默认能读414但不允许创建或开始，不能因此绕过前台与发布验收。完整414操作页面和正式兼容回退候选仍按[实施计划](plans/poker414-2-v1.md)后续阶段完成。
