# 模块结构与新游戏接入

本项目在同一进程和同一套持久存储中运行各款游戏。隔离的是职责、状态和权限；无需为每款游戏复制账号系统、服务器或备份资源。

## 三个边界

**共通房间平台**管理账号到席位的关联、房主、角色、准备、暂停、离席、可信动作、聊天、历史权限和房间清理。`app/rooms.mjs` 通过注册表调用游戏能力。统一身份只确认用户是谁，不能绕过席位或手牌权限。

**各游戏模块**位于 `app/games/<gameType>/`。规则决定合法动作和结果，页面负责该游戏的棋盘、手牌、拖放和反馈。完整多人引擎虽然位于 app 目录供本机与测试导入，但不会通过静态 HTTP 公开。拉密和军棋互不导入对方模块。

**共通页面工具**位于 `app/platform/`。时钟只消费服务端期限；页面会话维护账号代际、页面代际和客户端来源，避免迟到请求回写；退出控制保留未知结果的原请求编号；音频与视口控制管理设备生命周期。工具不决定摸牌、走棋或胜负。聊天、连接、身份与 Web App 外壳继续使用各自模块。原公共样式保留级联顺序，军棋专有样式归军棋目录。

[共通设置](../app/platform/room-settings.mjs)只负责入口、原控件收纳和弹层生命周期；HTML 声明或页面显式装配传入节点 ID，没有游戏类型分支。原音效、规则、重开、房间安排和权限处理器继续拥有行为；切入另一弹窗前在捕获阶段关闭设置，销毁时解绑并归还节点。拉密／军棋的房间与练习、第三款飞行棋共享此契约；[交互测试](../app/room-settings.test.mjs)与[飞行棋页面流程](../app/flying-page-flow.test.mjs)分别验证原节点／事件、禁用权限、层切换、清理和同骰选机保持。公开模块与样式显式列白名单；低频偏好不另造房间或用户状态。

[共通聊天](../app/room-chat.mjs)继续拥有消息、草稿、确认、通知和输入生命周期。新页面使用 `roomChatMarkup()` 与 `mountRoomChat()`，不再手写一份发送区；原拉密／军棋静态骨架保持兼容。页面以 `data-chat-notice-anchor` 声明有实际尺寸的工具区，以 `data-chat-dismiss-notices` 声明继续游戏时收起临时气泡的操作区；共通层跳过隐藏／零尺寸盒子，保留原页面选择器兼容，不按游戏名推测布局。气泡清理不清未读、草稿或棋局；无成员的本机练习不装配联网聊天。发送／关闭目标至少44px；紧缩聊天框优先保留输入、发送、关闭和状态，收起次要计数。页面流程替身只证明调用，真实聊天模块、成员HTTP／SSE和实际浏览器布局另有[通知测试](../app/room-chat-alerts-ui.test.mjs)及[飞行棋平台验证](../app/flying-platform.test.mjs)。新游戏按[平台接入记录](design/platform.md#共通能力接入记录)分层验收。

旧 `app/app.mjs`、`rules.mjs`、`army-room.mjs` 等是兼容转发入口。旧页面网址、存储键、动作字段与请求指纹保持；新增代码应导入对应模块的实际实现，不依赖兼容文件组织新功能。

## 服务端适配器

[契约](../server/games/adapter-contract.mjs)要求每款游戏明确提供引擎动作、公私视图、状态校验、配置、房间摘要、超时、存档格式和历史结算，并声明等待期玩家变动、初始房间字段与默认期限策略。实现见 [拉密](../server/games/rummikub/adapter.mjs)、[军棋](../server/games/army-flip/adapter.mjs)与[飞行棋](../server/games/flying-chess/adapter.mjs)。不支持配置或某动作时返回明确拒绝；没有缺省的牌池、手牌、摸牌、得分或胜负推断。

`createGameRegistry` 可注入独立适配器，房间平台本身不按游戏名分支。旧拉密测试的 engine 注入由拉密适配器明确承接，不是所有游戏共有能力。浏览器[目录](../app/games/catalog.mjs)只含公开名字、路由、人数、提示和资源路径，不能放入状态、服务器实现或秘密配置。

[历史格式兼容](../server/room-snapshot-compat.mjs)保持 schema1～8 的读取与映射；飞行棋采用独立 schema9，包含角色、完整比赛参与者及回合时钟。正式包声明读1～9／写2～9，旧两款按原格式保存；实际验证不支持schema9的旧包不能作为已写schema9的回退目标，不以清库解决兼容。实际生产存档不会因浏览器重排布局而改变版本。

平台只在可信构造参数提供 `serverRandomInt`；游戏适配器在当前玩家、阶段与房间权限检查后采样。持久层把候选动作、骰面和回执一起提交，失败CAS候选不广播；提交时的期限由同事务守卫检查。游戏 `round` 代表整段回合，连续六点不增加 `round`，所以共通时钟不重置。

飞行棋的 `page-ui.mjs` 供完整练习与朋友房间共用，只消费投影和操作回调。`game-page.mjs` 复用原会话、可信席位、独立退出和聊天控制；`practice-engine.mjs` 只在本机练习中驱动公开确定性核心，公平随机或固定教学骰序均不进入朋友房间请求。练习存档使用独立键和 Web Locks 排他写入；另一标签更新时先禁操作，再明确恢复。不支持锁或无法保存时明确提示，仍可临时练习。公开 `board/routes/rules/art/presentation` 的传递依赖逐个列白名单，服务器适配器、房间状态、夹具和测试保持私有。

启用 `usesActionIntents` 的适配器可得到本人最近128条操作回执投影；回执不包含其他成员请求、正文、指纹或身份秘密。[客户端意图工具](../app/platform/room-action-intent.mjs)先保存原请求编号／正文／预期版本，响应未知时只读对账并阻止新意图；明确重试沿用原请求，不从房间版本变化推断成功。浏览器存储不可读取或不可写时禁发新操作，房间仍可显示。新页面必须复用独立的共通退出控制，不能用受游戏意图锁限制的普通动作方法作为唯一离席入口；未知结果期间退出的页面流程另验。现有两款游戏保留原有动作接口与恢复行为。

## 接入一款新游戏

1. 完成[分类设计与资源 Step 0](design/game-design-template.md)，明确规则、内容、可见信息、超时、结算、随机结果和旧局兼容。朋友填写规则，维护者补技术实现。
2. 在本游戏目录实现纯规则、公开呈现和页面；为配置与公私视图实现服务端适配器并登记注册表。客户端提交意图，权威状态和随机结果由服务器决定。
3. 登记公开目录与资源；接入大厅、练习、路由和共通控制器。必须显式列入白名单，不能用递归公开目录代替检查。服务端、私有引擎、测试和夹具路径必须返回 404。
4. 实现存档校验、恢复与可信结算；需要新行为类型时补设计、规则和恢复测试，不能仅在数据里写一个尚未实现的动作名。
5. 跑规则、房间、HTTP/SSE、公私隔离、历史、备份和发布包测试，再检查实际输入、视口与资源。账号/登录/退出的生态改动另与 Agora 协调。

## 边界怎样防止退化

[第三游戏平台测试](../app/game-platform-boundary.test.mjs)保留没有牌池、手牌、棋盘或拉密分数的合成游戏，并由[真实飞行棋平台测试](../app/flying-platform.test.mjs)验证实际第三款的随机、两阶段动作、角色、期限、SQLite并发、新Node进程恢复和一次结算。[目录测试](../app/games/catalog-boundary.test.mjs)验证明确资源清单、真实 HTTP 的公开/私有边界，以及发布包排除嵌套测试和夹具。[控制器测试](../app/platform-controllers.test.mjs)验证时钟一次到期、页面旧结果失效、退出重试、音频和视口清理。原两款游戏的规则与完整流程测试继续保留。本地服务端注册与前台目录现均含三款，三款完整房间／练习页面均已接入正式大厅。浏览器保存的游戏类型不能丢失或把显式未知类型降级成拉密。[页面流程测试](../app/flying-page-flow.test.mjs)验证未知动作期间退出、同身份恢复、跨身份清选择和真实 HTTP 资源闭包；[实局备份测试](../app/flying-backup.test.mjs)在独立新路径恢复六阶段而不恢复会话。

测试递归发现 `app/` 的 `.test.mjs` 文件，但不执行夹具目录。仅测试使用的 `app/test-support/runtime-source.mjs` 让页面测试读取兼容入口后的实际实现，它不进入发布包，也不对浏览器公开。结构拆分不能用删除旧断言替代兼容验证。
