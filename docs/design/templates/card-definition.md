# 逐卡／逐物件定义模板

供[桌游类设计](tabletop-game.md)使用。朋友用普通话填写，不写程序；普通棋子、格子、骰子面、角色能力或资产也可用本模板，改相应名称即可。本轮每种可能入局的独立效果都应有一份定义，相同规则、不同数值可引用明确基础定义并列完整取值。

图案和卡面文字让人读懂，规则定义让各方在同一局面得到同一个结果。只有图片、名称、分类或一句“按牌面执行”，都不是完整定义。未来尚未加入的卡不必预写；本轮不完整内容明确标为不可入局。

## 可复制部分：朋友填写

### 1. 身份、分类与数量【必须】

- 固定类型编号 `typeId`：［维护者协助；改名不改编号］
- 显示名称：［填写］
- 所属游戏、规则版本、内容包与定义版本：［填写］
- 类别、标签、关键词及准确含义：［填写；注明只作筛选的标签］
- 数量、加入本局的条件与上下限：［填写］
- 本轮状态与确认人：［草稿／有争议／规则已确认／可入局］

### 2. 展示与资源【必须】

- 玩家看见的简短文字：［填写；关键词链接基础规则］
- 卡面必需数值、图案、名称、类型和费用：［填写］
- 与其他相似材料怎样辨认：［图形、轮廓、颜色、文字；不能只靠颜色或一行小字］
- 正面、背面、选中、不可用、拖影、预览与放大：［逐项资源或共同样式引用］
- 来源与可使用范围：［自制／AI／授权；标用途与限制］
- 资源加载失败时的可辨替代：［填写］
- [Step 0 上屏验证](../resource-stage.md)与批量资源状态：［填写；样板通过不等于所有资源已完成］

### 3. 使用条件、选择与费用【必须】

- 谁能从哪个区域使用；需要持有、拥有或操控吗：［填写］
- 可用回合／阶段／时机：［填写；非自己回合可用也要说明］
- 前提和限次：［每次／每回合／每轮／整局；归零时机］
- 谁选择、选择对象与数量：［填写；是否允许本人、队友或重复对象］
- 无合法目标或来源不足时能否使用：［填写］
- 费用、支付人、支付时机、是否必须全部支付：［填写］
- 确认前后能否取消，哪些费用或信息能退回：［填写］

### 4. 效果步骤与去向【必须】

用编号写全部步骤，每步包含“谁／哪个物件 → 做什么 → 去哪里或变成什么”。例如“从公共抽牌堆抽两张至使用者手牌，再由使用者选择一张手牌弃入公共弃牌堆”，比“换牌”清楚。

1. ［第一步］
2. ［第二步；若无填无］
3. ［后续步骤或待玩家选择；若无填无］

- 哪些步骤必做，哪些“可选择”；分支条件与各分支结果：［填写］
- 后续选择由谁做、合法范围、截止时间和超时默认；断线如何继续同一选择，等待时谁还能行动：［采用时必须确认；没有则无］
- 过程中目标不再合法、材料不足或某步无法完成时：［分别说明跳过／继续／终止／重选与退费］
- 卡／物件使用后到哪里；当前行动或回合是否结束：［填写］
- 是否检查胜负，何时检查：［填写］
- 效果和信息对哪些成员公开：［填写；私人结果不能靠日志或提示公开］

### 5. 特殊交互【采用时填写，其余明确写无】

- 允许回应／打断吗，窗口在哪、谁先回应：［填写或无；引用本游戏统一规则］
- 自动触发的事件、是否必做、触发时与执行时条件：［填写或无］
- 同时触发怎样排序，与其他卡怎样交互：［填写或无］
- 持续效果的对象、起止、叠加、来源离开和目标离开：［填写或无］
- 替换／阻止的原动作、优先、重复适用限制：［填写或无］
- 随机选择、复制、生成、变形或销毁：［填写或无；给出数量和身份后果］
- 引用的基础规则、关键词、其他定义与兼容限制：［填写］

### 6. 具体例子与未知【必须】

每例写开始局面、完整行动、合法性、费用、最终位置／数值、下一行动者和公开范围。

1. 正常使用：［填写］
2. 不满足前提或费用：［填写拒绝后哪些内容保持］
3. 无目标、材料不足或其他最易争议情况：［填写］
4. 多人交互／随机后的恢复／持续到期：［采用时填写］

- 未定问题、可能答案、确认人和影响：［填写；无则写无］
- 确认结论与日期：［填写］
- 玩家文字和效果定义的一致性检查人：［填写］

## 维护者补充：实现、存档与验收

- 每份实体 `copyId`：［生成方式；本局唯一稳定。两张同种牌不能共享一个副本 ID］
- 权威定义映射：［受支持行为及明确参数，或受审阅的专用行为函数］
- 状态字段与守恒：［归属、位置、顺序、朝向、附着、剩余次数、计数器］
- 持久选择：［选择者、合法范围、固定结果、已付费用、截止时间、完成状态；没有则无］
- 随机和记录：［何时固定，重复请求／重连如何继续同一结果；没有则无］
- 请求去重、修订与并发：［填写］
- 玩家／队友／观众投影、事件和日志字段：［填写］
- 私人整理、共享预览、正式结果的保存边界：［填写适用项］
- 单卡验收与关键组合验收：［对应上述例子；写证明方法］
- 内容目录／规则／资源清单版本与本局固定 bundle：［填写；本局不得随最新目录重解释］
- 存档格式版本与旧 bundle 恢复：［填写；格式迁移不等于换用最新规则或资源］
- 可入局目录检查：［类型唯一、数量合法、引用有效、行为受支持、资源完整］

朋友不能通过卡定义上传任意 JavaScript 让服务端执行。标签不是权限；页面按钮可用也不是服务端合法性的证明。新效果没有受支持的实现和边界用例，资源已画好也不能加入正式对局。

## 原创填写示例：轻量“行旅补给”事件

以下仅演示定义深度，是自拟教学卡和局面，不是棋牌室已有游戏内容。示例故意选择没有打断、持续或替换的简单机制。

**身份与资源：** `typeId = demo.travel-supply`，显示名“行旅补给”，教学基础包 v1，定义 v1，2 张，类别为事件，标签“补给”仅作筛选。牌面显示费用“1 枚补给标记”和“抽两张，弃一张”；行囊图案辅助辨认，正背面沿用教学卡框。资源状态为待制作，不可直接入正式游戏。

**使用：** 自己的行动阶段、持有这张牌、补给标记至少 1 枚、公共抽牌堆至少 2 张时可使用。每回合最多一次，不选其他玩家。确认前可取消；确认时将 1 枚补给标记移回公共补给池，将本卡移到公共弃牌堆，固定抽出的两张并将它们放入本人手牌。已经确认后，费用和已看见的牌不能撤回。

**后续选择：** 使用者必须从当前手牌选一张弃入公共弃牌堆；可选刚抽到的牌。本卡使用前已从手牌移走，不能再选择本卡作为待弃牌。完成弃牌后才算效果结束，回到该玩家行动阶段；使用本卡占用本回合唯一一次行动机会，之后仍需按教学基础规则执行“结束回合”。其他玩家此时不能插入行动。本示例没有打断、持续、触发、替换或胜负检查。

**信息与恢复：** 费用、本卡及弃牌公开；两张抽牌的正面只给本人，其他人只见手牌数量变化。弃牌选择期间保存已抽结果和待选择记录；刷新、重登或换设备继续选弃牌，不能重新抽取。教学规则给该选择 60 秒，从确认抽牌时由服务器计时；主动暂停冻结剩余时间，断线不暂停。超时由系统弃掉本次第二张抽牌，再结束回合；选择提交与超时只能成功结算一次。这是示例自己的约定，新游戏不默认采用。

**例子：**

1. 甲手牌为本卡、A、B，标记 1，牌堆顶部依次 X、Y。确认后本卡到弃牌堆、甲标记变 0、公共补给池增加 1，甲手牌 A、B、X、Y。甲弃 B 后手牌为 A、X、Y，弃牌堆含本卡和 B，甲再结束回合。别人看不到 X、Y 的正面。
2. 甲标记为 0 时请求使用，拒绝，牌堆、本卡、手牌与阶段保持不变。不因为费用不足而移动本卡。
3. 牌堆只剩一张时不能使用；教学规则没有自动洗弃牌堆或“抽几张算几张”的例外。已经抽出 X、Y 后掉线，恢复仍面对同一手牌和待弃选择，不再抽两张。

维护者将上述已确认效果映射到受支持行为并验证原子保存、待选择和秘密投影。这个例子说明需要写到哪一层，不要求所有简单卡都填写整套复杂机制。
