# 共通产品与运行设计

本文适用于大厅、多人房间和各款游戏的共通能力。**已有实现**以当前维护源码为依据；**设计要求**是修改与接入门槛；**待实现 / 待验收**不能作为现有产品承诺。各游戏的具体规则见[设计入口](README.md)。本页不包含部署实参、生产资源或真人记录。

## 1. 产品边界与基本流程

棋牌室面向朋友约局，要求稳定、操作清楚、手机好用。小圈子规模只影响容量，不降低权限、恢复、退出或交互质量。

正常流程是：打开邀请 → 完成棋牌登录 → 回到邀请的大厅或房间入口 → 明确加入或恢复原成员 → 准备 → 开局 → 轮流操作 → 结算 → 再来一局或退出房间。邀请后的登录不得丢失房间号；查看邀请不得自动占用新座位。

已有拉密 2～7 人、翻棋军棋 2 人；每房额外最多 8 位观众。大厅只展示已接入的游戏和练习。飞行棋、414、大富翁仍待各自接入，不占用现有游戏的规则标识。

## 2. 身份、成员与权限

**已有实现与必须保持的约束：**

- 共享身份以 `issuer + sub` 确认账号，再由棋牌建立本项目档案与成员关系。昵称只作显示，同名不能认领席位、聊天作者或战绩。
- 有效生态成员可以进入大厅，无需再次注册或申请棋牌资格；读房间私有数据和执行动作仍需该房间的可信成员身份。
- `roomId` 是房间内部身份，六位 `roomCode` 是找房入口；邀请码不是手牌、聊天或历史记录的访问凭证。关闭后的旧邀请码不得指向新房间。
- `selfId` 是稳定成员 ID；同账号换设备、重登或再次加入同房，恢复既有成员 ID 与角色。观众也有成员 ID，不占玩家名额。
- `selfRole` 分为玩家和观众。中心管理员、房主与当前行动者是不同权限：中心角色不继承房主或手牌权限，房主也不能替别人走棋或读取其手牌。
- 只有当前行动者能执行游戏回合动作。观众能看公开桌面、聊天、退出；不能准备、开局、修改规则、暂停、继续、接管房主或操作棋牌，也不作为参赛者取得战绩。
- 棋牌使用自己的登录客户端、授权码与 PKCE S256、项目会话及 CSRF 防护；不复用中心或日历客户端，不共享它们的 Cookie 或令牌。令牌留在服务端，浏览器使用本项目会话。
- 棋牌不删除或停用共享账号，不写日历业务数据。中心显示名不自动同步棋牌昵称；股票生态完全独立。

独立网址与受支持的挂载入口可连到同一运行服务、房间与账号业务库，但入口的会话、回调、事务 Cookie 和本地草稿命名空间各自隔离。跨入口访问不能借用另一个入口的会话 Cookie；恢复私有草稿首先回到其原入口。

对应代码：[身份与会话](../../server/session-service.mjs)、[入口上下文](../../server/entry-context.mjs)、[私有 HTTP/SSE 边界](../../server/unified-http.mjs)、[持久席位](../../server/durable-rooms.mjs)。

## 3. 房间状态与允许的操作

房间状态由服务器保存，客户端不得自行推断结束或销毁。有效业务状态是 `waiting / playing / paused / finished / aborted`；关闭、到期或找不到房间属于房间访问结果，不伪装成仍可操作的等待期。

- **等待 `waiting`**：新成员可选择入座或观战，并在容量允许时切换角色。玩家可以准备或取消准备；房主可修改支持的游戏设置、转交房主和开局。设置变化清除玩家准备状态。开局要求本游戏人数合法且全部玩家已准备。
- **进行 `playing`**：玩家名额锁定；新账号按观众加入，原账号恢复自己的既有角色。只有当前行动者执行本游戏动作。玩家可申请或撤回暂停同意、转交房主及明确离席；观众只能使用成员的只读与聊天能力。
- **暂停 `paused`**：不接受游戏回合动作；房间与已确认棋局保存。任一在席玩家可继续，观众不能继续。玩家明确离席仍会中止该局。
- **完成 `finished`**：展示可信结算并允许聊天、离席及房主发起下一局；不能继续上一局动作。下一局先回等待期，清准备状态，重新满足人数与准备条件。
- **中止 `aborted`**：展示中止原因，不计输赢；保留成员的恢复与离席入口。房主可回等待期邀请新伙伴，人数不足时仍不能开局。

以下四件事必须使用不同文案与操作：

1. **返回大厅 / 暂离页面**：停止当前页面的流或展示，保留房间和席位，不算输，不自动中止。
2. **退出棋牌登录**：终止当前入口的本项目会话及私有流，不退出中心或日历，不释放席位，不删除已确认棋局。另一入口和其他设备的会话不因此承诺同步退出；全设备退出尚未开放。
3. **退出房间**：明确释放本人成员关系。等待或结算后移除成员；进行或暂停中的玩家离席会中止本局且不计输赢，观众退出不影响牌局。确认框说明当前阶段的后果。
4. **关闭 / 回收房间**：最后一位玩家退出时关闭房间，结束余下观众连接。全员离线不等于全员离席，不立即销毁。过期回收停止访问并补齐待归档结果，不立即抹掉用于兼容、去重和归档的记录。

房主离席时自动交给仍在房中的玩家，优先在线者。房主可主动转交给另一玩家；其他玩家只能在服务端判定原房主失联并超过宽限后接管自己，不能指定任意人接任。当前持久房间的默认判定是 10 秒在线期限加 60 秒接管宽限；界面以服务端 `hostCanTakeOver` 为准。房主必须先转交才能变为观众。

默认普通房间在最后一次有效房间业务活动后 8 小时到期，最多 100 房；全体玩家同意暂停后按暂停阶段保留 7 天。读请求、聊天、在线心跳和整理预览不续期。暂停由玩家全员同意，观众不参与；任一玩家可恢复。更长保留期或更大容量须同时调整容量、清理、备份与费用设计。

验收要覆盖每阶段玩家和观众的加入、离席、最后玩家退出、房主转交、离线接管、超时回收及“再来一局”；至少使用两个同名账号确认不能互认席位。

对应代码：[房间状态机](../../app/rooms.mjs)、[持久房间与在线状态](../../server/durable-rooms.mjs)、[大厅退出文案与请求](../../app/lobby-model.mjs)。

## 4. 回合与时间

已有服务端计时：当前新朋友局每人回合默认 **30 分钟**。拉密到时摸一张，牌池空则过牌；军棋当前规则到时跳过。旧局或旧规则没有绑定时钟时，不强制添加倒计时；单人练习不强制计时。

`turnClock` 保存对局、行动者、回合、起始时间、剩余时间、到期时间与暂停状态。客户端只显示服务器期限，服务器以持久 CAS 决定到时推进；不能依赖手机后台定时器。暂停冻结剩余时间，继续使用剩余时间，不重新给满 30 分钟。

合法提交与超时竞争只能成功推进一次。已到时的普通游戏动作拒绝并要求同步；明确离席或房主转交仍使用各自权限检查。超时只使用已确认棋局，不能把未确认拖牌草稿作为正式出牌，也不能任意没收未提交牌。

侧栏按照服务端真实轮序排列并标当前、下一位；自己的回合有持续的视觉提示。多人动作到达、自己的新回合与最近新增公牌需要不同反馈。无倒计时惩罚的练习仍须明确轮到谁。

新游戏若有连续掷骰、连走或多个子阶段，必须先明确这些是否属于同一回合，以及总时限、超时采用哪个已确认状态；不能在每次子动作后隐式续满时间。

## 5. 动作、并发与未知结果

HTTP 接口均是**当前入口下的逻辑路径**，由入口 helper 生成实际地址：

- `GET /api/state`：本项目账号状态与本人最近房间。
- `POST /api/rooms`、`POST /api/rooms/{code}/join`：明确创建或加入；携带 `requestId`，请求正文不接受客户端提供的账号身份键。
- `GET /api/rooms/{code}`：读取经过本人席位投影的最新房间。
- `POST /api/rooms/{code}/actions`：共通或游戏动作；携带 `type / requestId / expectedRevision` 与该动作允许的字段。
- `GET /api/rooms/{code}/events`：经过当前成员授权的 SSE；可携带拉密预览订阅选项。
- `GET/POST /api/rooms/{code}/chat`：成员聊天；正文和游标独立校验。
- `GET/POST /api/rooms/{code}/preview`：拉密短时整理预览，不能作为游戏提交接口。
- `GET /api/history`：本人历史索引；历史详情也受参与者权限检查。

服务器按动作字段白名单检查输入、席位、阶段、当前行动者及游戏规则，并以房间存储版本 CAS 提交。`room.revision` 用于客户端并发控制，游戏状态另有 `game.revision`；存储 CAS 版本也独立存在，三者不得混为一个随意增减的值。

同一权限主体、同一业务操作的 `requestId` 绑定不可变正文。相同编号与相同正文重试返回既有结果；相同编号换正文拒绝。不能只按昵称、时间接近或界面按钮次数去重。服务端成功保存前不广播“已确认”。

客户端提交中禁重复操作。创建或入房成功后，跳转尚未完成时仍保持忙碌；恢复页面时释放退役导航。响应取消不证明写入未发生，取消也不能生成新的编号自动重做。

结果不明、网络丢响应或 `409`：先 GET 最新房间或账号最近房间，核对已确认状态，再由玩家明确决定下一次操作。不得自动重放业务 POST。创建 / 加入和聊天的明确确认重试保留原编号与正文；普通回合动作恢复后是新的玩家操作，不能盲目重复刚才的摸牌或走棋。

`429` 明确显示等待时间，不循环抢发。迟到回复必须同时通过账号代际、房间 / 对局、请求与流来源检查；旧 `finally` 不能解锁后来的新请求。身份核验成功后仍须重新检查席位，权限变化时不输出旧私有响应。

## 6. 持久保存与恢复

**已有实现**使用服务端加密存储和稳定密钥，持久保存房间、成员、规则设置、已确认游戏、时钟、正式布局、动作去重、聊天与历史。SQLite 是现有持久实现；内存适配器只作隔离开发，不能声称服务重启后还能保留对局。

跨设备恢复的是服务端已确认状态与本账号原席位。以下状态必须分开：

- **正式牌局**：提交成功即持久保存，服务重启与换设备后恢复；不同设备并发操作以同一权威 revision 决定胜者。
- **私有手牌排序、自由牌架位置、未提交游戏草稿**：设备 / 标签页本地，绑定入口、账号、房间、成员、对局和可见牌集合；不会自动同步到另一设备。
- **聊天草稿与未确认消息**：本标签页内保留，短暂 `503` 可按同身份恢复边界保留；没有跨设备草稿承诺。
- **在线状态、预览、会话、登录事务**：临时状态，不能从业务备份恢复来延长登录或把旧设备重新标为在线。

拉密的正式组合位置随出牌、摸牌或过牌原子保存；摸牌不能顺带提交未确认牌面。视口变化可对拥挤旧布局进行本机阅读重排，但单纯旋转不写共享坐标、不发布预览；首次明确公共编辑才把当前显示位置变成本轮布局，撤销可恢复原坐标。私牌整理不触发公共布局保存。

备份包含九类业务 scope，排除会话、登录事务和在线 presence。恢复先在独立新路径验证加密、摘要、版本、期限、成员与棋牌守恒，不替换运行库做演示。旧备份缺新功能数据时明确报告；恢复不能复活已过期消息、延长牌局期限或重复结算。

对应代码：[存储](../../server/storage.mjs)、[业务备份与恢复校验](../../server/backup.mjs)、[公共布局](../../app/table-layout.mjs)、[私牌布局](../../app/rack-layout.mjs)。

## 7. 连接、认证失效与错误恢复

**已有实现与验收要求：**

- 普通 SSE EOF / 网络中断：显示连接状态，保留仍可用的当前画面和合法草稿，停止过期预览，按受控间隔重新连接。重新取得快照建立安静基线，不重放入场音、旧聊天或动作音；断流不是退出登录。
- 可见桌面切换窗口焦点：维护源码会重新核验身份，同时保持已经核验的牌桌和草稿，避免普通 focus 造成整页 loading 或拆掉 SSE。核验若确实失败，仍按下述失败边界处理。
- 真正隐藏、`pagehide` 或后台：立即隐藏私有内容并停旧流；返回后先核验当前账号，再恢复。系统可能暂停或杀掉 Web App，不承诺强制所有平台永久后台运行。
- `401`：停止私有流、清私有展示与旧账号草稿，提示明确重新登录；保存的牌局与席位不删除。不自动跳中心、重复退出或提交动作。
- `503` / 核验超时：隐藏私有内容并暂停；重新核验后，只有同账号、同席位、同 `matchId / gameRevision` 且草稿仍合法时恢复。换账号或已换局不得带入原手牌与草稿。
- `403`：提示当前权限不足，不用改昵称或创建新账号绕过席位检查。`404`：房间关闭、到期或席位失效，提供大厅恢复 / 新邀请入口。
- 重复 / 迟到响应：账号代际变化、请求取消、旧流来源失效后不得重新显示数据，也不得把旧 `401/503` 施加到新身份。

本项目当前有 15 秒前台核验与私有 SSE 看守、10 秒账号请求上限；服务端私有操作按身份契约核验，再对实际房间成员复查。在线检查不采用长期“上次成功”缓存替代即时权限。默认会话绝对上限 60 分钟、闲置上限 30 分钟，并受上游身份有效期限限制；回合计时不延长登录，无自动刷新令牌把长局变成永久会话。

**待验收**：真实近期认证、实际撤销、多位伙伴多设备、反向登录、手机独立窗口，以及身份服务异常和三项目共享容量。核心路径或合成测试通过不能开启中心全设备退出，也不能宣称共同安全验收完成。

对应代码：[账号生命周期](../../app/account-client.mjs)、[房间流](../../app/room-client.mjs)、[身份策略](../../server/identity-policy-client.mjs)、[会话](../../server/session-service.mjs)。

## 8. 公私投影与短时预览

权威完整游戏状态只在服务器。静态资源白名单不能公开房间状态机、完整多人引擎或服务端配置。浏览器拿到的是按本人角色生成的 view：

- 拉密玩家只能看自己的 `rack`；其他人只有手牌数量。观众没有私有 `rack / opened / playerId`，牌池只能见数量，不能见牌池实体 ID。
- 军棋未翻暗格只投影为隐藏状态，不包含阵营、棋种或真实棋子 ID；观众不能取得可执行翻子 / 走棋 / 拾旗列表。
- 所有人可见的动作记录只含公开摘要；不得夹带账号身份键、隐藏棋牌或完整聊天正文作诊断。
- HTTP、SSE、预览与聊天每条路径分别校验，不能因为进入大厅、打开房间号或订阅一个流就继承所有权限。

拉密预览只展示**当前行动者主动放到公共桌面的牌**和原公共桌面；不广播其剩余手牌或私牌排序。预览可以暂时非法，但标为“正在整理、尚未确认”，接收方只读；不替换正式游戏、本地草稿或回合权限。

预览绑定房间、对局、游戏 revision、行动者、会话来源、序号与 30 秒有效期。换回合 / 换局 / 离席 / 过期 / 断流 / 身份失败时回到正式桌面。它不存档、不续期房间、不增加正式 revision；频繁拖动合并最新状态并限流，多个设备不能互相覆盖同一预览来源。军棋不使用此通道展示暗棋。

对应代码：[角色投影白名单](../../app/game-registry.mjs)、[预览服务](../../server/room-preview.mjs)、[预览客户端](../../app/rummikub-preview-client.mjs)。

## 9. 聊天、确认与软键盘

已有房间成员聊天，不受当前游戏回合限制，等待、进行、暂停与结算阶段都能使用。非成员不能凭房号读消息，退出或身份失效后结束消息访问；观众聊天不授予游戏权限。

- 输入正文按 CRLF→LF、NFC 规范化后验证，最多 500 字符、2048 UTF-8 字节、3 行；禁止控制字符和不成对代理字符。原始输入草稿保持原样，新 outbox 才绑定规范化正文；明确重试沿用原正文与编号。
- 历史最多保留 24 小时及最近 500 条；客户端有分页和过期提示。发送限制为每人 10 秒 5 条、每分钟 20 条，房间每分钟 120 条；去重记录也有上限。聊天不续期牌局。
- 发送状态分“发送中 / 已确认 / 未确认可重试”；只有同房、本人稳定成员、同 `requestId`、同正文的回执才能确认。POST 与 SSE 任意顺序到达只形成一条消息，不能按同名或同正文猜成功。
- 已确认的本人消息有对话内气泡；聊天收起时可短暂显示“我 · 已发送”，不算新未读、不播放朋友发言音。重连历史不重放确认提示，失败时不能显示已发送。
- 朋友的新实时消息在抽屉收起时显示短预览和未读数，可打开查看。主动查看旧历史时不强制滚到底部；每设备可关闭消息提醒但保留未读。私有预览在后台、换身份、断线或关闭时及时清除。
- 文字以文本节点渲染，不解释 HTML。聊天不能清空拖牌草稿、确认出牌或接管游戏 Escape 行为。
- 输入法组成期间不提交，不用 Enter / keyCode 229 误发消息，不用新消息渲染覆盖输入候选。身份或房间更换时退休输入代际并取消旧组成；迟到 `input / compositionend / final input` 不写进新草稿。自动 focus 或 render 不能解除围栏，明确的新编辑或新组成能恢复输入。
- 面板按真实 visual viewport 适配软键盘、平移、缩放与横竖屏，缩小非必要间距，让输入框、发送、关闭和状态仍在可见区域。游戏主画面无滚动不等于禁止聊天历史自身滚动。

对应代码：[聊天服务与限流](../../server/chat.mjs)、[聊天模型与界面](../../app/room-chat.mjs)、[IME 与键盘回归](../../app/room-chat-alerts-ui.test.mjs)。真实 iOS / 安卓键盘体验仍须另验。

## 10. 一屏、操作反馈与声音

**设计要求**：游戏主画布、公共桌面 / 棋盘、自己的手牌、轮序与核心行动在同一屏内，不依赖页面滚动才能操作。大厅和聊天历史可以按内容滚动。不能只隐藏 overflow，把按钮或牌裁掉后声称“一屏完成”。

已有固定视口布局、安全区处理、横屏提示、自动缩放、自由整理和放大看牌；拉密密集布局按整组阅读，组间至少一个逻辑牌宽，标签不能碰牌或相邻标签。公共布局与私有牌架分开保存；旋转和键盘恢复不得改变实体 ID、分组或共享布局。整组拖影保留颜色与鬼牌子型展示，去除交互身份并设为 inert，不能冒充新的命中目标。

核心操作应同时有明确文字、颜色 / 轮廓和可选声音；不能只靠颜色或声音表示合法目标、当前回合、未读、错误、确认与胜负。鬼牌类型有图形区别与文字名，数字使用统一基线且不靠数字下横线识别。选中、可行动与刚变化的棋牌应有不同视觉语义。

已有 22 类原创合成音效，分类为：本机选择 / 整理 / 撤销 / 拆合；准备 / 开局 / 暂停 / 继续；公开摆牌、翻棋、移动与碰撞；摸牌 / 确认 / 非法动作；轮到自己；聊天；胜 / 负 / 和。公共已授权的新摆牌预览或正式动作由事件来源去重，接收成员可听；本人的私牌整理只在本机反馈。

声音可以静音、调整音量并按设备保存偏好。必须经浏览器允许的可信手势解锁；维护源码包含触摸与指针释放恢复，不用定时器绕过系统限制。有限声部、限频、混音和重要提示优先级防连续噪音；返回与重连不补播积压通知，关闭后不复活音频上下文。首次恢复未启声时给可见的启声入口。

**待验收 / 待完善**：真实手机持续音频与静音模式听感、完整键盘操作、屏幕阅读器顺序、触摸目标和对比度。现有按钮焦点及文本替代并不证明全面无障碍；验收必须在无声音、颜色难辨和非鼠标操作时仍能完成关键流程。

对应代码：[视口](../../app/game-viewport.mjs)、[看牌与事件反馈](../../app/game-presentation.mjs)、[音频](../../app/game-audio.mjs)、[样式](../../app/styles.css)。

## 11. 资源与桌面 Web App

当前棋牌、桌面和交互主要由本项目 CSS / 代码绘制；鬼牌使用本项目生成的图片，音效由代码合成。参考商业游戏的是交互与规则，不复制其品牌、头像、图案、录音或背景。新资源须登记来源、生成 / 作者、许可与可公开分发范围；AI 生成不能替代资源权利核对。公开仓库许可不自动覆盖未声明的第三方资源。

图片、样式、脚本、页面、API 与存储 key 使用统一入口解析，兼容独立根入口和挂载路径；不能写死根 `/assets/` 导致挂载时取到中心资源。所有鬼牌路径要验证手牌、桌面、预览、拖影和放大实际解码；四种类型不能只靠一行小字区别。

已有可添加桌面的 manifest、图标、独立窗口及离线连接提示。Service Worker 仅处理本入口的导航失败，所有资源与 API 保持网络获取，不缓存手牌、聊天、令牌、认证页或私有 API。挂载入口的 worker scope 不能取得中心或其他项目根路径控制权。离线不能操作多人局，也不能把旧缓存局当作当前授权。

自托管者需自己的持久目录、稳定密钥、HTTPS、受信入口与登录配置、进程管理、备份和监控。不得把虚构身份预览端口公开当生产，也不得将真实存档或密钥放进仓库。新增游戏默认共用现有房间与存储；若引入额外服务或提高容量，先说明固定与按量成本，不承诺“增加游戏永远零费用”。

对应代码：[入口 helper](../../app/entry-path.mjs)、[安装支持](../../app/app-shell.mjs)、[worker](../../app/sw.js)、[静态资源白名单](../../app/server.mjs)。

## 12. 模块与扩展接口

共通房间层负责成员、角色、准备、房主、phase、对局身份、回合计时、离席、动作去重、公开摘要和房间回收；持久服务负责 CAS、索引、在线 presence 和归档补齐。各游戏负责初始状态、合法动作、信息投影、回合推进、守恒和可信结束结果。

现有适配器提供 `createGame / applyGameAction / privateView / spectatorView / stateProblem`、合法动作字段与人数 / 规则版本；军棋另外支持 `applyTimeout`。未来游戏必须明确自己的超时动作，不能误借拉密默认摸牌，也不能把完整引擎加入公开静态资产白名单。

结算由权威引擎产生。房间 CAS 保存最终状态与待归档摘要，再以唯一 `matchId` 归档并补齐本人历史索引；这是可重试的持久任务，不冒称多记录在一个同步事务里。观众不入参赛名单，下一局生成新 `matchId`。正常完成记录赢家 / 平局与原生结果；明确退房、过期或中止不伪造输赢。

已有个人战绩保留 180 天，访问限本人参与的记录，不归档过程手牌、暗棋或完整聊天。**累计娱乐积分待实现**：若后续加入，按游戏 / 规则 / 计分版本区分，从可信结算唯一派生；不把不同游戏点数直接相加，不作入房资格，不充值、兑换、转账或提现。公式、期限、重算、去重和展示范围先写明，不能默认上线一张全生态排行榜。

对应代码：[适配器](../../app/game-registry.mjs)、[游戏路由](../../app/game-routing.mjs)、[结算历史](../../server/match-history.mjs)。

## 13. 新游戏接入与版本门槛

一款游戏进入大厅前，按以下顺序完成并留可检查证据：

1. 填[游戏设计模板](game-design-template.md)，明确人数、全部实体、开局、每回合完整流程、合法 / 非法例子、胜负 / 平局、隐藏信息、观众、超时、变体与未定项。
2. 固定 `gameType / ruleVersion` 与开局设置；未定规则不能交给前端临时猜。新局使用新版本，旧局继续原玩法。
3. 实现权威引擎与公私投影，接入适配器、路由、房间动作字段、计时、SSE 和历史；客户端只提交动作，不提交赢家、骰子结果、暗牌真值或积分变化。
4. 同步快照校验、牌 / 子 / 钱等实体守恒、规则设置和随机结果持久化。读写版本、备份 scope 与启动预检一起更新；骰子等随机结果需同一编号重试不重掷，等待选择的中间阶段有正式状态。
5. 复用准备、观战、邀请、聊天、离席、暂停、账号恢复与单项目退出；完成独立练习及每屏核心操作。不先造另一套用户模块。
6. 用本地合成身份完成规则、并发、持久化、私有隔离、重启与旧局恢复测试，再做真实浏览器与手机验收。没有该游戏的证据，不能沿用另一游戏的通过数。
7. 新增付费依赖、资源、权限或其他项目改动分别审查；公共发布包只包含必要源码、设计、测试和允许分发的资产，排除真实存档、凭据与现场记录。

现有房间快照读取 schema 1～8、写入依功能使用 schema 2～8；规则版本与快照版本不同。未来扩展须明确兼容矩阵，不能为新游戏伪装成旧类型或静默升级旧局。不能读取当前存档、缺身份守卫或不支持当前入口的旧包，禁止作为自动回退目标；回退需要兼容代码、相同业务库与稳定密钥，不删除存档换取启动。

## 14. 上线验收清单

每一项分别标记通过、失败或待验收，并记录环境与范围；自动化、本机浏览器、真实手机、真实成员和中央联合证据分开。

- **完整约局**：新邀请、登录回原房、同账号恢复、等待入座 / 观战、开局后自动观战、满房 / 满观众、准备变化、开局与结算、再来一局、明确离席及全离关房。
- **权限**：两个同名账号、非成员、普通玩家 / 房主 / 观众 / 中心管理员、跨房号与内部 ID、两入口会话；HTTP / SSE / 预览 / 聊天 / 历史都不泄露手牌或暗子。
- **动作与时间**：重复点击、同编号换正文、双设备同时行动、`409`、超时与提交竞争、暂停剩余时间、结果不明 GET 对账。确认成功一次，失败不自动重放。
- **恢复与数据**：服务器重启、当前 / 旧规则存档、换设备恢复席位、断流重连、后台返回、`401 / 503 / 429 / 404`、迟到回复、账号切换、结算归档竞争与独立路径备份恢复。
- **一屏与交互**：桌面、平板、手机横竖循环、最小视口、软键盘缩小 / 平移、PWA 冷启动、满桌 / 大手牌、自由拖动 / 整组拼接 / 拆分、确认与撤销 / 刷新。所有关键元素真实可见和可用，不以隐藏滚动条判通过。
- **聊天与声音**：中日文 IME、规范化文字、失败重试、POST / SSE 两种顺序、旧组成迟到、未读与自发确认、静音、恢复手势、重连不重放、无音时可完成流程；通知和键盘不得遮核心操作。
- **资源与发布**：每个受支持入口实际加载所有资产，worker scope 与 no-store 生效，包无秘密 / 真数据，输入清单与运行文件一致，支持当前存档，更新与回退不改其他项目。
- **真实联合门槛**：近期认证、实际撤销、邀请回房、双成员 / 多设备手牌与席位隔离、身份异常恢复和共享容量由相关项目联合完成。未完成时明确保留，不开放全设备退出，也不把公开匿名页通过写成真人登录通过。
