# 从一句游戏名，到一版可开发的设计

“做个三国杀”“做个大富翁”可以是需求入口，但游戏名不能替代规则。维护者负责查资料、拆解和查漏，朋友确认具体玩法；不要求朋友先写出技术引擎。

## 1. 先圈定本次完整范围

- 参考哪一版规则、哪一种模式、哪一个内容包，查阅日期和来源是什么？
- 几人玩，谁和谁一组，怎样开局、行动、结束？
- 本次完整提供哪些内容，哪些留到未来？用明确目录，不用“先做常见的”。
- 哪些是参考规则，哪些是朋友改法？不明确的地方列问题与确认人。

例如“三国杀式游戏”要先选模式与初版武将、游戏牌及装备范围。初版的全部可入局内容必须定义完整，不要求穷举历年所有模式、武将和扩展。此处仅说明拆解方法，没有启动三国杀开发；棋牌室下一款游戏仍优先飞行棋。

## 2. 把机制写成有唯一结果的规则

以下是内容型卡牌游戏的检查方向，不是默认套用到所有游戏的规则。逐项确认适用性和具体答案：

- **回合与阶段**：谁行动，能做什么，能否跳过，结束后轮到谁；他人在本回合能否回应。
- **区域与物件**：手牌、牌堆、弃牌、装备、角色及其他区域；归属、控制者、顺序、容量、公开范围和移入移出条件。
- **角色状态与结束**：体力或资源、伤害、恢复、救援、死亡、离场与胜负；是否立即结束或等结算完成。
- **目标与距离**：谁能被选，目标数、范围、排除条件；选定后目标失效怎样处理。
- **费用与次数**：何时扣费，何时算“使用过”，每回合还是每阶段重置；取消、无效或中途失败是否退费。
- **回应与效果顺序**：谁先回应、能否拒绝、多人同时触发谁排顺序，连锁何时结束，防止无限循环的处理。
- **装备与持续效果**：槽位、替换、附着、移除、效果叠加或覆盖，以及来源离场后是否继续。
- **随机与后续选择**：结果何时固定，选择者、合法范围、截止与超时；掉线后继续原结果，不能重新抽取或掷骰。
- **秘密与提示**：每个角色能看什么；日志、动画、提示、观众和公开预览也不能泄露秘密。

用一局完整演示和争议例子检查这些机制。比如“造成伤害”不能只写扣一点：仍要确认伤害能否被改变、何时触发技能、能否救援、何时判定结束。

## 3. 逐种定义内容，同时验证机制够不够

先列全部目录，再为有独特行为的一种武将、牌、装备或地块复制[逐卡／逐物件定义](templates/card-definition.md)。重复副本共用类型定义，对局中每一份副本仍有自己的稳定编号。

每项至少写清：分类与数量、使用或触发时机、前提、费用、目标、选择、按顺序发生的效果、最终去向、公开信息、失败/超时处理、合法/非法例子以及资源映射。武将有多个技能时逐个定义，装备的被动效果也不能只写一句介绍。

底层机制与内容定义相互校验，不是先凭空造一个“万能引擎”再机械填牌。具体卡提出的新需求，需要回到机制说明补规则、实现与组合验收。已支持的效果可复用参数；新机制不能仅凭一行卡牌文字自动运行。

## 4. Step 0 先做资源样板和操作小样

最小规则、材料与关键操作明确后，执行[资源阶段](resource-stage.md)：牌框、文字层级、角色图、装备图、背面、标记、选中/可用状态和基本音效先做代表性样板，放进手机主画面验证。文字和数值由布局呈现，插画不负责定义行为。

样板与关键规则确认后，可以进入完整实现，并按计划补齐全量资源。完整接入前，本轮所有可入局内容的规则定义和资源都必须齐备；不能让未定义或占位内容进入朋友牌局。

## 5. 从完整闭环逐批扩展

先做范围明确的一版：范围/目录与最小规则 → 资源样板 → 补齐本批规则与内容并实现权威逻辑、界面与保存 → 全量内容和资源校验 → 单项与关键组合 → 手机、多人和异常验收。规则、具体内容与资源相互校验。先期可做隔离原型验证困难机制，不能以局部演示宣称产品完成。

新增内容时判断：只是已支持效果的新参数，还是新增阶段、区域、回应或胜负规则。后者要同步改设计、实现和验收。对局固定规则、内容与资源版本组合，进行中的旧局不因新扩展被重新解释。

理论上可以自行实现这样的游戏；困难随特殊内容和相互作用增加。先限定初版并做完整，比以“支持所有卡牌”作为第一版目标更可检查。模板帮助提前发现问题，不能承诺自动穷举所有技能组合或消除迭代。

## 参考与边界

核对日期：2026-10-06。[三国杀国战官方进行游戏说明](https://guozhan.sanguosha.com/game_rule/game.html)分别讲回合阶段及阶段内行为，并指向逐牌效果。这里只借鉴“机制与具体内容分别说明”的组织方式；该页是特定国战说明，不作为所有版本的统一规则，也不复制其牌面和完整规则。

[BGA ItemManager](https://en.doc.boardgamearena.com/ItemManager)把对局物件的唯一身份、位置、顺序作为明确字段。本项目据此区分类型定义和副本状态，未接入该 PHP 框架。更多来源见[参考笔记](reference-notes.md)。
