# Step 0：资源制作与上屏验证

适用于[固定牌类](templates/fixed-deck-game.md)和[桌游类](templates/tabletop-game.md)。样板与上屏验证在完整游戏实现前通过，全量资源在完整接入前齐备；由玩法设计者与维护者共同确认，朋友不用运行代码。这是开发流程要求，不表示待开发游戏已有资源或已经可玩。

先明确最小骨架：人数、基本材料及数量范围、重要信息、典型操作。由此列出资源需求，制作代表性样板，直接上屏验证阅读和操作，进入完整实现并按计划补齐本轮资源库。规则与资源可相互修订，不能先做大量插画再发现必要信息放不下。

## 0A. 本轮资源清单

每类资源复制以下条目；相同牌框/数字/花色可引用共用样式，不必为每张副本另生成图片。

- 稳定资源编号、名称、所属类型或内容包：［填写］
- 用途：［牌框／牌背／花色／数字／特殊牌／角色／棋盘／棋子／标记／图标／声音等］
- 数量与变体：［哪些共用，哪些确有不同图形或文字］
- 对应游戏定义编号与版本：［填写；图片文件名不能充当权限或牌局实体编号］
- 表现方式：［代码绘制／SVG／字体／位图插画／合成音效／录音；填写理由］
- 正常、选中、可行动、暂不可用、最近变化、隐藏状态：［各显示什么；不需分别生成位图的也说明］
- 逻辑尺寸、比例、边距、可辨最小显示尺寸、放大方式：［填写实测目标］
- 颜色、形状或图标、文字辅助：［特殊类型不能只差一行小字或一个颜色］
- 来源／作者或生成方式、字体/音频/图片使用条件、可公开分发范围：［填写］
- 存放路径与发布清单：［仓库内相对路径；透明背景需求、格式和备用呈现］
- 状态：［未做／样板／通过上屏／本轮齐备］；确认人、日期、证据位置：［填写］

数字、规则文本与数值由统一字体/布局或程序呈现，便于修订并保证准确；插画、纹理和角色图形可用AI生成或人工绘制。行为由已确认规则定义，不能从图片文字或AI识图推断效果。AI生成也要检查来源、使用条件与可公开范围。

## 0B. 代表性样板

先挑能暴露问题的一组素材，无需一开始批量生成全部插画：

- 普通牌/棋、最长数字或名称、最长规则文本；多种花色/阵营和同名副本。
- 每种特殊实体的代表，含图案相近但行为不同的类型。
- 牌背/暗棋、选中、合法目标、未确认操作、最近公开变化等状态。
- 棋盘/公共桌面、本人区域、对手与观众视角、主要操作栏。
- 最常见动作、轮到自己、发言、错误、结算的声音与视觉提醒。

填写：样板编号［　］；选择原因［　］；暂缺资源与补齐时间［　］。

无牌桌游把“牌”替换成棋子、骰子、地块、建筑、资源标记；不需要插画的游戏可以全部用代码/SVG。资源制作不能省略视觉区分、尺寸与操作验证。

## 0C. 可操作小样与验收

维护者把真实样板放进轻量场景，玩法设计者确认看得懂、选得准。临时逻辑明确标为原型，不宣称完整规则、联网或保存已经完成。

1. **通常与极端数量**：桌面、手牌和长说明分别达到设计上限，阅读清晰，组距与信息层次明确。主游戏一屏可操作，详细文本按设计用查看层阅读。
2. **全部呈现场景**：本人/公共区域、对手已揭示内容、观众、拖影、共享预览、动画与放大；图案、颜色和文本一致，秘密不泄露。未采用的场景注明无。
3. **触摸与方向**：手机、平板、电脑；横→竖→横、安全区和聊天键盘，主要目标与确认/退出入口真实可见。小图难辨时采用已确认的放大/选择方案。
4. **声音与静音**：基本动作确实触发；本人/公开动作、去重、音量与密集动作有方案。静音也能理解回合和结果，需手势启声的入口可见。
5. **加载与失败**：各受支持入口的相对地址正确，图片实际解码、字体可用；失败保留可辨类型/文字与重试提示，不用缺图框或同一个表情代替特殊牌。
6. **准确与一致**：数字字号/基线、花色和图案统一，牌面描述与已定行为一致；文本修改后重新核对定义版本。

每项记录设备/视口、方法、结果、问题与确认人。模拟视口只证明布局，真机触摸与听感另列待测；截图好看不能证明拖动、密集牌量或加载正常。

## 0D. 两个完成门槛

**样板通过，允许进入完整实现**：最小材料和操作目标明确，代表性资源及可操作场景通过检查；风格、尺寸、信息分层、缺图处理和全量补齐计划有结论。未知关键类型不靠开发者临时猜图案或行为。

**整套资源齐备，允许完整接入与交付**：本轮所有可入局类型都有完整规则/内容定义和资源映射，所需资源齐备；全部呈现场景与受支持入口通过验收。缺少美术或规则的内容保持未启用，不随机出现在朋友对局中。

确认记录：资源清单版本［　］；通过的样板［　］；未完成项与责任人［　］；允许实施／交付的范围［　］。

资源、内容与规则分别版本化，每局绑定兼容的一组版本。新图片不改变旧牌效果；新类型/效果先补定义和验收，再进入新局。隔离原型可验证未知项，不能把占位资源当作产品完成。
