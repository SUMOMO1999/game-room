# 棋牌室设计入口

这里说明棋牌室如何运作，以及一款新游戏需要满足什么条件才能接入。设计依据是仓库中的规则引擎、房间服务、持久存储和界面代码，不以某次演示或测试数量代替产品验收。

## 从哪里读

1. [共通产品与运行设计](platform.md)：账号与席位、房间生命周期、回合、保存、恢复、公私信息、聊天、声音、布局和接入门槛。
2. [拉密](games/rummikub.md)：拉密的规则版本、牌组、鬼牌、整理与提交语义。
3. [军棋（双人翻棋）](games/army-flip.md)：分阵营、翻子、移动、碰暗棋、排雷、夺旗与运旗。
   [飞行棋朋友版建议](games/flying-chess.md)：未实现的 2～4 人规则草案、关键待确认分歧与[资源 Step 0 样板](../assets/flying-chess.md)。
4. [分类模板入口](game-design-template.md)：[固定牌类](templates/fixed-deck-game.md)重牌组与规则；[桌游类](templates/tabletop-game.md)重内容目录与行为，配合[逐卡定义](templates/card-definition.md)。朋友先填规则、例子和未知，维护者补技术与验收。
5. [迭代经验](lessons.md)：实际问题为何出现，以及怎样转成下一款游戏的设计检查项。
6. [Step 0资源阶段](resource-stage.md)：样板上屏与操作小样通过后开始完整实现，全量内容与资源齐备后完整接入。
7. [游戏名拆解指引](from-game-name.md)与[参考笔记](reference-notes.md)：从一个名称圈定一版完整范围，借鉴成熟平台而不照搬其全部机制。

游戏文档补充共通设计。若同一概念出现冲突，先核对权威代码，再明确修改规格与兼容策略；不能只改说明而让运行行为保持相反结果。

## 当前范围

- **已有实现**：拉密 2～7 人、双人翻棋军棋、单人练习；房间邀请、玩家与最多 8 位观众、准备与房主、暂停与继续、服务端回合计时、牌局持久保存、可信席位恢复、成员聊天及个人战绩。
- **维护源码中的体验修复**：聊天输入法代际保护、规范化正文确认、自发消息确认提示、紧凑键盘布局、触摸释放启声，以及前台切换窗口后的柔性账号核验。是否已进入某个部署版本，应检查那个版本的代码和验证结果；本设计页不替代发布确认。
- **待实现**：414、飞行棋、大富翁及其他桌游；累计娱乐积分、朋友榜、语音、私信、完整回放等。没有完整规格、引擎和验收的游戏不能作为可玩入口展示。
- **仍待联合验收**：完整真人跨项目登录、近期认证与实际撤销、多人多设备私有信息隔离、手机独立窗口的全部恢复路径、身份服务异常及共享服务容量。已有本地隔离测试、部分真人观察或公开页面检查不自动完成这些门槛。中心全设备退出继续关闭。

飞行棋已进入规则与实现准备，可使用桌游模板轻版，卡牌章节明确不适用；大富翁仍需确定具体版本、规则与素材来源。两者都不能借用拉密或军棋的测试结果宣称完成。414 应先使用固定牌类模板澄清当地玩法，尤其人数、牌数、牌型比较、回合结束和计分；不根据游戏名称猜规则。

## 阅读状态标记

- **已有实现**：在当前维护源码中存在对应行为，并能定位权威模块。它不意味着任意自托管实例已经配置正确，也不意味着所有真机和联合验收通过。
- **设计要求**：后续修改必须保持的约束，或发布前必须验证的目标。若代码不满足，应明确登记缺口，不能把文字当作修复。
- **待实现 / 待验收**：当前不能对玩家承诺的功能或尚缺的证据。

每款游戏至少要写清：固定规则版本、完整玩家流程、合法与非法例子、隐藏信息、超时、掉线、结算、旧局兼容及上线验收。共通功能不是省略这些说明的理由。

## 仓库与自托管边界

公开设计不包含生产账号、主机地址、登录客户端编号、密钥、真实玩家数据或现场操作记录。示例身份与房间只能是合成测试数据。

本项目的账号生态范围是 Agora、日历和棋牌；股票项目保持独立。复用身份不等于复用业务权限、Cookie、令牌或数据库。其他人自托管时，需要自己的身份服务、独立登录客户端、入口配置、持久存储和密钥；本仓库不提供现有生态成员账号或生产配置作为公共演示。

当前生产启动与身份恢复包含本项目专属的可信入口约束。迁移到其他域名或身份提供方时，应明确适配配置与校验代码并做隔离验证，不能仅替换页面链接，也不能关闭权限检查换取“能登录”。本机虚构身份模式只用于隔离开发，不能作为公网认证方案。

## 维护约定

- 新游戏先确定最小规则与材料，完成Step 0样板和操作验证，再完整实现；具体内容反过来检查机制，完整接入前全部可入局定义与资源齐备。新功能先补规则、状态变化、权限与失败处理，并补与真实缺陷相关的测试。
- 规则、界面和数据版本分别管理；新玩法作用于明确绑定它的新局，旧局不得静默变规则。
- 新游戏复用大厅、房间、账号、观战、聊天、恢复和战绩的共通能力，不另造一套账号或离席语义。
- 发布检查应同时覆盖正常流程、未知结果、重启恢复、旧存档和公私隔离。真实设备与中央联合验收单列，保持未完成项可见。
- 更新设计时描述最终行为和限制，不追加生产发布流水；部署实参、凭据和真实记录不进入公开设计目录。
