# 棋牌室操作与动态体验规范

2026-10-11。用户明确：现有及后续每款游戏都应有产品感。本文是共同设计合同；已写规范不代表各游戏已整改或上线。实际进度见[整改计划](../plans/gameplay-experience-v1.md)。房间工具与屏幕几何继续引用[布局规范](room-layout.md)。

## 玩的是桌面上的对象

首先让玩家看到实际的牌、棋子、画布、货物和正在发生的事情。常驻区表达归属与状态，当前任务放在相关对象旁；主要操作能在物件上发现。拖动有抬起、可落区与取消反馈，同时有点击路径；误触、横滑和转屏不能提交动作。

牌面保留画面主角、名称、关键效果与代价。货物牌以图标×数量和价格为主；人物／道具用短而准确的机制摘要，完整牌文补边界。短屏改变区域比例和当前任务步骤，仍保留当前对象与必要信息。编号、分类、长说明不能占据主角位置。

普通摸牌、留弃、出牌、选目标、收益、回应和拍卖在桌面完成。设置、主动阅读和关键退出确认可使用适量弹窗；每个额外模态须说明收益，不能只因为现有组件方便。不要一操作就模糊整张桌面，或者让玩家不断进入、关闭、再进入详情。

当前任务必须直接读出：谁用了什么、为什么轮到自己、可选择什么、要付什么、确认会得到／失去什么。己方收益、对方作用与回应机会分别表达。相关物件有归属、数量、选中状态和合法／不合法原因，不用一组无图货名代替材料。

短屏信息预算先去重复：人物用稳定席位与可辨称呼，完整姓名在席位／成员中可查；当前牌效、成本和后果不能藏到详情。读牌、选材料及确认各自保留当步必要信息，以真实长昵称的目标→回应操作核关键按钮可达，不用裁切或缩字掩盖挤压。

## 每个关键动作有因果反馈

每款游戏在设计时列出最常发生的2～3条闭环：起始对象→输入→待确认→权威接受／拒绝→结果位置→下一步。实际页面至少完成这些闭环的动态样板，之后才扩大机制。图鉴和静态截图不充当可玩体验证据。

反馈分为触摸反馈和已确认状态反馈。触摸可抬起、跟指、预览并取消；收到有效规则结果／服务器投影后才翻开秘密、搬运资源或落位。提交中保留同一个对象并说明正在确认；失败回到可操作位置，未知结果沿原请求对账。物件运动应能追踪起点与终点，完整过程中的关键说明一直可读。

默认使用简短、有层次的物件运动与结果提示：触摸约80～160ms、迁移／翻面约180～320ms作为初始设计参考，不作为性能硬门。每次优先一个主动作，伴随一次适当的声音或数值变化；不循环闪烁、不让所有面板同时飞入。动画不延迟合法输入、阻塞规则时钟或驱动收费／随机／换人。

手牌排序是本机阅读变化，公开落牌才是游戏行动；公共出牌与秘密摸牌的动画按角色区分。自己可翻合法私牌，别人仅见统一牌背及数量；公开后才能显正面。拖影与动画DOM不保留已经退出角色的私有材料。

首载、刷新、重连与后台返回直接显示当前有效状态；不重演历史，不重复发音／计数／收费。重复投影不重播，换局／换账号／销毁取消运动。减少动态模式直接落到相同结果，仍保留文字、数值与选中反馈；声音可关，结果始终可见。实现生命周期沿现有投影与代码质量合同，不另造游戏状态。

## 声音与物件一起设计

拉密过去的音效指摘属于产品体验验收，不能当作附加装饰。每条关键闭环同时写声音含义、触发点、强弱与去重：本机选择／整理立即轻反馈，确认后落牌／摸牌表达已完成，轮到自己和重要结果另有层级。失败不发成功声；一次动作只保留合适的主要声音，不能落牌和拼组叠响。

复用[共享声音](../../app/game-audio.mjs)及[共通控件](../../app/platform/room-audio-controls.mjs)的静音、音量、浏览器解锁、节流、混音上限和后台清理。逐款核真实事件和物件落位的对应关系；首次载入、重复投影与后台恢复不补播。静音下视觉任务和结果保持完整。

实际听一段连续操作及一次成功／失败，检查声音是否协调、拥挤、刺耳或错位，重要提示是否被压住。源码有音效、声音单测通过和试听按钮可用均不能单独证明听感通过。拉密拆组／跨组拼接的重复主音已在本轮整改，实际进度和音频证据归[整改计划](../plans/gameplay-experience-v1.md)；浏览器合成输出不能冒称手机扬声器或主观听感验收。

## 用实际游戏过程验收

1. **第一次会操作**：从真实练习／朋友房入口，首次玩家不打开牌文或外部教程即可指出当前对象、任务、必要成本和后果，完成一条正常回合及一次外来回应。不能把发现入口责任交给用户试玩。
2. **看得见变化**：正常速度看一次录屏／逐帧证据，指出物件从哪来、落在哪、何时被接受；动态过程不遮挡任务和下一操作。静态目视另外核艺术、比例和读牌；几何通过仍可能设计失败。
3. **能取消和恢复**：连续点击、拖出后取消、一次失败／未知结果、刷新或后台返回，以及减少动态模式。结果、材料和请求次数符合权威状态，不留拖影、不重播秘密。
4. **覆盖实际消费者**：同一显示模块的正式／练习和相关观战，桌面与受支持的手机风险尺寸；改共通层逐款实际装配，行为不同的第三实现验证边界。六主题沿原检查方法核可读性，不重做全量业务。

每项记录入口、场景、环境、截图／动态证据、结果与未验范围。方法新增先通过一个真实闭环再推广；已覆盖而无新问题的测试不无限重跑。发布门槛由维护者执行，不增加逐阶段向用户索取许可。
