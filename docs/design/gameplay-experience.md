# 棋牌室操作与动态体验规范

2026-10-11。用户明确：现有及后续每款游戏都应有产品感。本文是共同设计合同；已写规范不代表各游戏已整改或上线。实际进度见[整改计划](../plans/gameplay-experience-v1.md)。房间工具与屏幕几何继续引用[布局规范](room-layout.md)。

## 玩的是桌面上的对象

首先让玩家看到实际的牌、棋子、画布、货物和正在发生的事情。常驻区表达归属与状态，当前任务放在相关对象旁；主要操作能在物件上发现。拖动有抬起、可落区与取消反馈，同时有点击路径；误触、横滑和转屏不能提交动作。

牌面保留画面主角、名称、关键效果与代价。货物牌以图标×数量和价格为主；人物／道具用短而准确的机制摘要，完整牌文补边界。短屏重排区域比例并去除重复说明，已知材料仍在同一任务选齐，保留当前对象与必要信息。编号、分类、长说明不能占据主角位置。

普通摸牌、留弃、出牌、选目标、收益、回应和拍卖在桌面完成。设置、主动阅读和关键退出确认可使用适量弹窗；每个额外模态须说明收益，不能只因为现有组件方便。不要一操作就模糊整张桌面，或者让玩家不断进入、关闭、再进入详情。

当前任务必须直接读出：谁用了什么、为什么轮到自己、可选择什么、要付什么、确认会得到／失去什么。己方收益、对方作用与回应机会分别表达。相关物件有归属、数量、选中状态和合法／不合法原因，不用一组无图货名代替材料。

选择目标或公开材料时，先提供本机草稿：看清可选库存、重选、取消，最后确认才提交并收费。所有已知材料在同一任务中选齐，只有一次提交确认，不额外插入「查看材料→核对费用→再次确认」。确认前的取消不扣行动、不耗尽道具、不交换库存；刷新／换任务清理草稿。只有已经揭示秘密、抽随机结果或权威结算的步骤不能当作未发生，此时须直接说明已付费用与剩余选择；「重新选择」只清本机选择，不能声称撤销原动作。主动放弃拍卖是游戏决定，须与取消尚未提交的报价区别。

材料池按实际投影数量显示，不把某次三张示例写成上限；支付牌、收益、双边货物和装备替换分区独立标明归属、数量与选中，首末候选均可操作。确认前取消清草稿、回到来源物件重新操作；术士拆除后的借用则保留已付人物行动与拆除结果，只取消尚未确认的借用材料。

短屏信息预算先去重复：人物用稳定席位与可辨称呼，完整姓名在席位／成员中可查；当前牌效、成本和后果不能藏到详情。读牌、选材料及确认各自保留当步必要信息，以真实长昵称的目标→回应操作核关键按钮可达，不用裁切或缩字掩盖挤压。

窗口适配也是操作体验：常见比例与分辨率使用有限稳定构图，任意拉伸用有下限的舞台FIT或紧凑构图承接，具体按[布局合同](room-layout.md#受控游戏舞台与支持范围)。来源牌、效果、代价、确认与结果位置作为一个完整任务预算高度，不能只保住桌框和下方手牌。拉伸期间取消临时运动但保留选牌、材料、报价和输入焦点；尺寸变化不是新回合，也不触发游戏提交。

## 教学让玩家知道正在学什么

教学中央持续给出本课目标、当前合法对象、下一动作及其原因，第一条操作不能依赖设置中的提示。确认仍走真实规则，草稿可取消；教学不替玩家自动提交随机、支付或移动。目标达成后明确「本课完成」、真实收益／状态差异和学会的规则，提供下一课、重练及完整练习。教学里程碑与领域待决状态分开：停在学习节点时不残留普通对局的空待办，也不为显示完成擅自结清领域动作。刷新恢复完成姿态、不重复执行，教程与普通练习分开保存。

实际验收从冷入口不用提示完成首课，开始／选择／确认／完成四种画面均可说出下一步；逐课核目标、原因和不同收益，另外检查过关刷新、重练与下一课。按钮存在、合法轨迹通过不足以证明教学清楚。

## 每个关键动作有因果反馈

每款游戏在设计时列出最常发生的2～3条闭环：起始对象→输入→待确认→权威接受／拒绝→结果位置→下一步。实际页面至少完成这些闭环的动态样板，之后才扩大机制。图鉴和静态截图不充当可玩体验证据。

反馈分为触摸反馈和已确认状态反馈。触摸可抬起、跟指、预览并取消；收到有效规则结果／服务器投影后才翻开秘密、搬运资源或落位。提交中保留同一个对象并说明正在确认；失败回到可操作位置，未知结果沿原请求对账。物件运动应能追踪起点与终点，完整过程中的关键说明一直可读。

默认使用简短、有层次的物件运动与结果提示：触摸约80～160ms、迁移／翻面约180～320ms作为初始设计参考，不作为性能硬门。每次优先一个主动作，伴随一次适当的声音或数值变化；不循环闪烁、不让所有面板同时飞入。动画不延迟合法输入、阻塞规则时钟或驱动收费／随机／换人。

手牌排序是本机阅读变化，公开落牌才是游戏行动；公共出牌与秘密摸牌的动画按角色区分。自己可翻合法私牌，别人仅见统一牌背及数量；公开后才能显正面。拖影与动画DOM不保留已经退出角色的私有材料。

首载、刷新、重连与后台返回直接显示当前有效状态；不重演历史，不重复发音／计数／收费。重复投影不重播，换局／换账号／销毁取消运动。减少动态模式直接落到相同结果，仍保留文字、数值与选中反馈；声音可关，结果始终可见。实现生命周期沿现有投影与代码质量合同，不另造游戏状态。

## 声音与物件一起设计

拉密过去的音效指摘属于产品体验验收，不能当作附加装饰。每条关键闭环同时写声音含义、触发点、强弱与去重：本机选择／整理立即轻反馈，确认后落牌／摸牌表达已完成，轮到自己和重要结果另有层级。失败不发成功声；一次动作只保留合适的主要声音，不能落牌和拼组叠响。

复用[共享声音](../../app/game-audio.mjs)及[共通控件](../../app/platform/room-audio-controls.mjs)的静音、音量、浏览器解锁、节流、混音上限和后台清理。逐款核真实事件和物件落位的对应关系；首次载入、重复投影与后台恢复不补播。静音下视觉任务和结果保持完整。

实际听一段连续操作及一次成功／失败，检查声音是否协调、拥挤、刺耳或错位，重要提示是否被压住。源码有音效、声音单测通过和试听按钮可用均不能单独证明听感通过。拉密拆组／跨组拼接的重复主音已在本轮整改，实际进度和音频证据归[整改计划](../plans/gameplay-experience-v1.md)；浏览器合成输出不能冒称手机扬声器或主观听感验收。

## 用实际游戏过程验收

1. **第一次会操作**：从真实练习／朋友房入口，首次玩家不打开牌文或外部教程即可指出当前对象、任务、必要成本和后果，完成一条正常回合及一次外来回应。不能把发现入口责任交给用户试玩。
2. **看得见变化**：正常速度看一次录屏／逐帧证据，指出物件从哪来、落在哪、何时被接受；动态过程不遮挡任务和下一操作。静态目视另外核艺术、比例和读牌；几何通过仍可能设计失败。
3. **能取消和恢复**：连续点击、拖出后取消、一次失败／未知结果、刷新或后台返回，以及减少动态模式。结果、材料和请求次数符合权威状态，不留拖影、不重播秘密。
4. **覆盖实际消费者**：同一显示模块的正式／练习和相关观战，桌面与受支持的手机风险尺寸；改共通层逐款实际装配，行为不同的第三实现验证边界。展开真实选牌／外来回应后降低桌面高度、连续拉伸并恢复，确认来源与动作完整、缩放后可读可点、草稿未丢且无额外请求。六主题沿原检查方法核可读性，不重做全量业务。

每项记录入口、场景、环境、截图／动态证据、结果与未验范围。方法新增先通过一个真实闭环再推广；已覆盖而无新问题的测试不无限重跑。发布门槛由维护者执行，不增加逐阶段向用户索取许可。

## 桌游逐牌验收的范围与频率

首次实现完整牌库、重写共用出牌／材料流程，以及正式大版本前，按实际定义逐牌跑页面闭环。货物买／卖、道具安装／替换／激活／借用、人物主动／回应按独立操作列出；分支、同牌不同目标及秘密揭示另外列，不用「待决类型都出现过」代替逐牌完成。当前幽街为51种、110张；110张重复实体不逐张重跑相同效果。

每个操作核合法材料与不足材料、取消后重选、提交前后费用与实体归属、连续输入只提交一次。涉及秘密的牌核玩家／对手／观众投影；涉及回应、竞价或多人目标的牌核相应角色与轮序；已保存的待决核刷新／掉线恢复不重复随机和收费。局部材料选择不能越过另一玩家的决定。失败须保留原状态，未知结果按原请求对账。

小修复只跑受影响的牌、相邻共享流程与必要恢复回归；改布局跑真实最多装备、较多手牌、多组材料和低高度，逐个测牌面、按钮及内容包含关系，不能只测父容器。缩放或扩大触控热区后，相邻实际命中框不得互盖，边缘点按须命中正确对象，正文及数量仍清楚可见。改共享组件扩大到全部实际消费者。用规则／接口检查覆盖多种材料边界，浏览器覆盖逐牌交互和高风险几何，真人设备与主观动画／听感另记，避免把全部层重复成全量组合。新增失败修复后复验失败面；没有新变化不重复整轮。

预期结果从冻结规则和牌文独立计算，不用被测结算结果生成期望。逐牌另核实体守恒、货物供给与归属、银两及行动下限；非法操作、材料不足和过期选择不能改状态或消耗随机。涉及边界时至少包含空／恰好够／差一／满位、本人／对手／第三席／观众，以及主动／回应／已揭示阶段；按机制挑必要组合，不将每张牌与全部设备笛卡尔相乘。

多回合、组合效果、牌堆耗尽、临时位与胜负触发在首次完整规则和规则大改时跑有界完整轨迹，保留种子与最小失败步骤；后续只在对应机制变化时复测。慢响应、重复点击、拒绝与未知回执分开核，提交中换局／失焦／刷新不能串任务。测试失败保留原记录；文案断言失效与业务失败分别修复和取证，补测结果与原失败关联，不能覆盖成一次全量通过。
