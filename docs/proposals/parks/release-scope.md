# PARKS 最终上线范围与完整性交付门

2026-10-09，用户已明确：**原盒可选玩法也全部一起上线**。本文件是最终范围，不是完成声明；开发可以分阶段，正式可玩版本不能少模块后仍称完整。原版事实见[模式规则](modes.md)和全量目录；项目裁定见[边界解释](decisions.md)。

## 1. 用户能选择的完整玩法

共同采用二版三季与完整基础目录，规则包拟定 `parks-2e-full-v1`，开局冻结模式及全部设置。

- **标准多人：2～5位真人。** 各2名徒步者，正常竞争及照片名次计分。
- **双人Teddy：2位真人＋1组Teddy。** Teddy是规则自动行动者，不占真人席位、不准备、不聊天、不列人类得分名次。
- **官方单人：1位真人＋2组Teddy。** 用官方单人阈值与最终徒步等级；玩家需要选择两组Teddy的执行顺序时有真实入口。它不是一个人对普通电脑。
- **露营开关：上述全部模式可开／关。** 开启后使用全部4块双面露营板的合法抽取与三季变化，以及3帐篷，不只实现一个样板营地。
- **志愿项目：上述全部模式可选0～4张。** 0关闭；1／2／3／4对应四档挑战。开局从全部9张中随机不重复抽取，公开显示本局改变了哪些规则。按原书可用于多人，不能只在单人入口实现。
- **热忱开局：随机1张或发2选1。** 原规则允许熟悉游戏后2选1，首发设置提供两种，默认1张。2选1时先固定候选，所有玩家完成选择后才开始首个行动；未选牌移出本局。玩家自己的选择候选可见，确认保留的热忱公开；其他人的未选候选与弃选牌不投影。

创建界面先选“和朋友玩”或“官方单人”，再显示合法设置。双人Teddy只在2人模式开放；单人Teddy不能关闭；不允许3～5人误开双人Teddy。准备期人数变化使设置不再合法时清准备并要求选择匹配模式，不悄悄换玩法。开局后固定人类人数与模式，后来人只观战。

上述6种人数／基础模式入口（1人单人、2人标准、2人Teddy、3／4／5人标准）×露营2态×志愿项目数5档＝60类配置；这仅是配置类数，不包含随机9选N、热忱选择和实际牌序的全部组合，不能称60次测试就穷尽所有玩法。

## 2. 必须一起交付的模块

1. **全部内容与版本**：基础63公园、37装备、10热忱、24水壶、12季节、路线与骰子；4块露营板8面、21张Teddy正反关联、9张志愿项目、单人参考与帐篷。每份均有定义、数量、来源、表现资源、行为映射、恢复状态；未知卡不能靠禁用来凑完整。
2. **权威规则**：基础行动、费用与替换、连锁及限次、营火、天气、水壶、公园市场、露营分支、Teddy移动与顺序、志愿项目修改、季末、各种模式终局。
3. **正式房间**：模式设置、准备／取消、房号邀请、角色切换、房主转交与接管、旁观、最近房间、返回大厅、明确离席、暂停与继续、中止与重开。
4. **所有模式页面**：主路线、露营区、Teddy指示及当前卡、志愿项目摘要、热忱候选、公共市场和个人背包；密集状态仍可读且可操作，不能“机制在服务端但页面没入口”。
5. **独立练习**：大厅直接进新手教学、本机官方单人、对普通电脑、继续存档。露营／Teddy／志愿项目均有教学和本机可玩入口；普通电脑练习支持同一套合法双人配置，不替代官方单人。
6. **完整图鉴／帮助**：全部基础及可选牌、触发与差异、逐步上下文规则、中文文字、原名索引；原始版权图不作为自有资源。
7. **共通真实接入**：聊天和双向气泡、设置、六主题、分事件音效、稳定退出、状态通知、视口与键盘。准备、进行、暂停、结果、观战均有对应入口。
8. **长局与恢复**：已确认部分动作、未完成选择、单人选择Teddy顺序、Teddy已翻与下张牌背关系、帐篷／露营季序、志愿项目限制及所有时钟进入同一版本快照。随机之后刷新、并发设备、进程重启不变结果。
9. **结算与记录**：多人可信分项和并列；单人分数、官方等级、志愿项目难度标记，Teddy不虚构分数。不写414永久积分。正式记录沿平台的成员可见历史及保留期，带模式配置；本机练习只在本机，不伪装正式成绩。
10. **完整资源与可用体验**：公园风景63幅、13类装备主体与37种明确牌文、全部可选卡与棋子、牌背、状态反馈和必要音效。缺图可辨替代只是容错，不代替全量资源制作。横屏游戏、竖屏规则／图鉴及可见退出。
11. **真实发布接入**：原网址与Agora同域两入口、公开路由白名单、安装版更新、版本匹配、备份、回退、已有六款回归；不能只上API或只上练习，正式与练习入口同批可达。

## 3. 验收如何防止末尾漏项

后续技术计划必须为上述11项和每个模式列“实际模块／状态→入口→验证场景→证据→通过或缺项”；不另造一份与计划不同的实施进度。本文件只维护最终范围。

- **规则与材料**：逐份静态数据和数量核对，全部独有行为可调用；每张志愿项目单独验证，再覆盖会改变同一费用／触发／结束条件的组合。不能只测关挑战的基础版。
- **完整局**：标准2人和5人、双人Teddy、官方单人均走完三季；露营跨三季和志愿项目真实效果必须进入完整轨迹。完整纸面推演与已运行规则引擎分别记录，不用一个手工结算截图代替。
- **配置**：60类人数／玩法配置的合法初始化、保存与恢复；热忱1张／2选1各覆盖。所有不合法组合明确拒绝且不改局；不拿60类配置检查冒充全部卡牌组合已穷举。
- **自动行动**：Teddy进行到翻牌、选顺序、移动、移除天气／市场、取帐篷、终点、洗回或季末任一中点重启，不多走、不漏走。浏览器动画结束不能决定自动行动是否提交。
- **共通画面先验**：先检房号、元素、控件圆角与居中、聊天／设置／退出，再测功能结合；完整准备／热忱选择／本人／他人／Teddy／观众／季末／暂停／结果／练习状态不能只验主桌面。
- **实际设备与输入**：短横屏、平板、大屏、6主题代表组合、键盘聊天、横竖往返、浏览器返回、声音重启及资源失败；模拟视口与真机分别列，不把截图通过写成真实触摸通过。
- **协议与恢复**：双身份、双设备、观众、权限变化、401／503、未知提交、SSE重复／断流、新进程与独立路径恢复；普通暂停／超时暂停／热忱选择超时分别检查。单人房也沿同一账号及权限体系。
- **制品与线上**：完整不可变内容包／资源清单、旧局可读、能读新格式的回退包、两入口实际资源可用、正式配置开启读回。缺一个必交模块就不把该版本发布为“完整PARKS”；不能到发布阶段临时删减本清单。

## 4. “设计完整”与“成品完整”的区别

最终RV必须同时报告：已修设计缺口、仍缺的原始牌文／关键裁定，以及后续需要用真实实现证明的项目。设计能消除已知歧义、固定范围与验收出口，不能预先保证零缺陷。

当前本文件不授予代码或素材已完成的状态，不要求用户逐阶段批准例行实施；它要求维护者按计划完成全部范围，并让未完成项保持可见。v0.4已用具体公开数字对象及8图对应补齐露营分组，并按来源置信层级明确采用；后续实物独立验证不冒称已完成。关键牌文、实体关系或行为若以后发现未知，应回到设计处理，不用自拟卡或编号猜配代替。当前可进入技术计划；资源、实际装配和完整模式运行门仍须分别通过。
