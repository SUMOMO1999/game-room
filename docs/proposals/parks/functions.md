# PARKS 页面与功能合同

状态：2026-10-09，v0.4 全模式功能合同；以下是明确交付范围，不代表已经实现或通过测试。玩法事实以[主设计](README.md)、[模式规则](modes.md)和[内容目录](content.md)为准；[完整交付清单](release-scope.md)是最终范围。本页补齐“哪里进入、谁能做、点完发生什么、失败怎么继续”。

## 1. 首版交付清单

首版包含：标准多人、双人Teddy、官方单人、露营与全部志愿项目，完整三季对局、观战、独立练习、分步教学、全量图鉴、规则帮助、分项结算、暂停与恢复，以及真实接入的共通聊天／设置／主题／声音／退出。没有完整规则与内容的状态只开放设计阅览，不把静态样板标成可以玩。

不新增原盒之外的多人组队、交易、创意工坊、用户编辑卡牌、排行榜、跨局经济及公开历史录像；保留旧六款游戏行为。原盒可选模块在首发全部交付，每局设置可关闭；开发不能把开关关闭当作已经实现。

### F01 大厅、创建与加入

- 大厅有“和朋友玩”“官方单人”“先练一练”“规则与图鉴”真实入口。只有发布验收通过后才显示可开局；图鉴不能冒充练习。
- 创建房间固定 `parks-2e-full-v1`，标准2～5真人或官方单人1真人、最多8观众。准备期房主选择Teddy／露营／0～4志愿项目／热忱1张或2选1等合法配置，具体约束见交付清单；不自由改季数、牌库、背包限额或得分公式。
- 房号邀请沿用共通身份与同一房间，不另设登录。未开始时可选择入座或观战；满座显示观战选项。开始后新成员只观战，已有参赛账号恢复原席位；换设备不生成第三名徒步者。
- 退出应用、返回大厅、断网均不等于退出房间。实际关闭空房沿用平台生命周期，不能因为一台设备断流销毁牌局。

### F02 准备室

- 常显房号、复制邀请、参赛成员与顺序、观众、人数、准备、开始、规则版本、三季／约40～70分钟参考时长。
- 昵称过长省略但可查看；颜色有不同形状辅助，颜色选择不能把别人或观众变为玩家。
- 人数满足所选模式、所有真人参赛者准备后房主可开始；官方单人不等一个假Teddy账号准备。加入／离开参赛席或修改有效配置清准备；观众聊天不清准备。按钮禁用必须给原因，不能只有灰色。
- 点击开始后重复提交沿用同一意图；只有服务端成功建立本局后发牌、定随机和进入主屏。响应丢失查询原结果，不重复建局。
- “已准备”可取消；等待期可在有容量时玩家↔观众切换，房主先转交才能观战。“设置→房间安排”必须实际提供转交房主，以及服务端允许时的失联接管，不能只导入设置容器。角色／接管沿[平台权限](../../design/platform.md#3-房间状态与允许的操作)。
- 热忱2选1在开局后先固定每人的两张候选，再按冻结真人席位逐人选择，Teddy不参与；全部完成后才进入首个徒步回合。当前选择人显示30分钟期限，其他人可以聊天和看公开资料，不能改已确认模式；超时保存候选并暂停，不重新抽卡。

### F03 对局主屏

- 常显季节、当前行动人、回合步骤、期限／暂停原因、两名徒步者位置、营火、自己的五类资源摘要与容量。
- 中央路线地点显示顺序、动作、天气、占位、摄影地点标记；终点三个位置显示动作和首到奖励是否已取。先手标记、摄影徽章、摄影地点是三个不同对象。
- 公园／装备／水壶市场各3个槽，空位仍有稳定位置；一个区切换查看不能改变另一区牌序。
- 成员栏按实际座位展示，指出本季仍可行动的下一位；已经到终点的人显示“本季完成”。轮到自己及被要求选择时强提示，别人最近移动和获得材料短时突出，并可查文字记录。
- 任意成员与观众可以只读查看公开区域和原始牌面定义。没有本人行动／选择任务时能看图鉴、规则、设置及聊天，不能代选、重掷或挪棋；季末有待本人完成的选择时，该责任人可以按奖励窗口操作，不要求属于普通主动回合。

### F04 移动与动作选择

- 点击自己的在途棋子 → 高亮合法目的地 → 展示地点／天气／营火后果 → “确认前往”。点空处或取消只清本机草稿。
- 本人全部在途棋子没有合法前进分支时，按D04显示“前往终点”出口及原因；先检查公园预订、露营和确定奖励，不能只因一个分支不可用就跳过。交易预览展示足额费用、受库存／项目限制的实际所得，允许合法的部分输出。
- 确认后从“移动”进入“处理地点”，服务端留存已移动位置；刷新不能换目的地。需要挑水壶、资源支付、装备或热忱时，均显示具体对象、可选数和确认后果。
- 支付支持自动推荐与手改；默认优先普通资源、保留野生动物，但不是强制。预览同时展示印刷费用、减免、实际支付及付款后的剩余资源。不可用的支付组合说明少哪种资源。
- 不能因为用户关闭详情弹窗就视为放弃必选项。未完成的必选项回到主屏仍有入口；可选收益有明确“放弃这次机会”，且说明不能取回。
- 没有隐藏的自动点击：是否继续游览、填哪行水壶、选哪张展示牌、热忱分支由规则指定玩家确认。无需选择的确定性变化可自动结算并留下记录。

### F05 公园、装备、水壶与热忱详情

- 公园显示原名、中文暂译、积分、五资源费用、即时效果、有无预订／已游览，以及当前可否支付；放大图仅承载风景，数值用真实文字。
- 装备显示费用、准确触发条件、本回合可用／已用、会付什么和得到什么；“停在某地点”与“执行某动作”用不同图标及文字，不只放相似资源图。
- 水壶显示所在行、该行是否已填、每枚效果及剩余槽。新水分配逐枚选择，背包旧水没有填壶入口。
- 热忱显示目标进度依据及两条分支预览；达标立即选择，一次确认。目标未达时可预览，不能提前选；选后公开并固定，刷新不重新弹出二选一。
- 每件已获得内容都能在个人面板找到；不把许多装备挤成一行小图。筛选／排序属于阅读偏好，不修改规则所有权、位置或已用次数。

### F06 回合结束、季末与结算

- “结束回合”先检查必选项、基础动作已执行或按D04合法跳过，以及背包上限；有未用可选收益时列出来供确认。确认放弃以后不允许回到上一步补用。
- 超当前有效容量时明确让玩家选择归还的资源，展示丢弃后总数及上限来源；基础为12，志愿项目可修改。即时野生动物上限与回合末背包总量分开检查，不等到结束才处理即时限制。
- 季末分开显示资格统计、奖励领取、奖励引出的选择与重布步道。系统已完成的步骤带结果，未完成选择显示实际责任人；不使用永远转圈的全屏loading。
- 终局列公园、照片、照片名次奖励、热忱、秋季奖励、先手标记六个分项，能展开每张计分依据；胜者／并列与打破平局依据明确。
- 仅房主发起“再来一局”，回准备室并清准备；固定上一局结果，不把已选热忱或剩余背包带入新局。结果页一直有聊天、设置和退出。中止页显示原因、房主“回准备室”和所有人的离席入口；最后真人离席关闭房间并结束观众连接，Teddy不使空房永久存活。
- 单人结果显示个人分项、官方徒步等级及志愿项目难度标记，不显示照片名次奖、假对手分数或赢Teddy的胜负。正式记录沿平台历史权限／保留期并带规则配置，本机练习只存本机。

### F07 暂停、离席和恢复

- **普通暂停沿已有平台合同：全体真人玩家同意后暂停，任一真人玩家可继续；** 可申请／撤回同意，观众与Teddy不参与。官方单人本人同意即可。普通暂停恢复原剩余时间，不重给30分钟。
- **PARKS超时是单独例外：** 主动回合、开局热忱选择及每人的完整季末奖励窗口各30分钟，子选择不续满；到时保留已确认结果及待选并自动暂停，不替玩家消费随机。必须由本次超时责任人点击继续，给该责任窗口新的30分钟；其他玩家仍可转交房主或退出，不替离线者反复重开计时。此权限差异需要适配器实际实现，不能声称平台现成支持。
- 普通房间沿有效业务活动后8小时到期，暂停状态（包括本游戏超时暂停）保留7天，界面展示服务端过期时间。聊天／读取／心跳不续期，不承诺无限保存；要分次玩时使用暂停。重启或恢复快照沿原期限，不能重新赠送保留期。关闭回收使用共通归档流程。
- 自动Teddy及纯系统步骤不等待客户端动画，也不由客户端时钟推进；需要真人选择两组颜色顺序时，同一完整Teddy执行批次共享独立30分钟，不因每次小选择重置。同位置棋子按M01稳定编号自动选。自动步骤不为真人消耗其下一主动回合额度。暂停及离席在安全原子边界生效，已经提交的自动步骤保留。
- 返回大厅保留席位；“退出本局”二次确认并说明中止而非判胜负。确认后不能经浏览器返回重新操作。观众退出只离开观战。
- 短暂断流显示小提示、保留已知局面，关闭会重复提交的按钮；恢复后按新版本重算草稿是否合法，不整页清空重来。
- 401按共通入口恢复身份，未恢复前不展示身份私有区；503不登出、不退房、不清存档。换焦点不重新初始化游戏。服务器已提交而回复丢失时查原意图结果。
- 不承诺浏览器能在所有手机后台无限运行；服务器保管期限和正式局面，前端恢复同一状态。原账号、多设备、邀请回房均须实际验证。

### F08 聊天、设置、主题、音效

- 房间右上紧凑连续排列“聊天→设置→退出”，不均匀散在整行。练习没有虚假联网聊天。
- 关闭聊天窗也能看自己和别人气泡、未读提示；猜测输入法或软键盘高度不决定布局，以实际可见区域避让，输入文字和发送按钮必须都能看见。
- 设置收纳音量、启声／静音、规则、六主题与房间安排。轮到本人、移动、资源、装备、公园、照片、季末、结算及聊天均有对应反馈；声音失败不影响动作。
- 复合收益可合并声效，不能每枚资源轰炸；原动作POST和SSE同事件只响一次，重连不重播历史。主题不改变资源语义色，需描边／形状保证辨认。

### F09 独立练习与教学

- 真实入口为“先练一练→新手教学／官方单人／对普通电脑／继续保存进度”；教学完成可进入完整局。官方单人采用专用Teddy与单人结算，对普通电脑是一人＋一位按人类规则行动的电脑，可启用合法双人Teddy、露营与志愿项目。电脑只消费该电脑角色有权看到的投影（包括自己的起始热忱候选），不看对方未公开候选、牌序或随机种子；规则驱动Teddy与策略电脑是独立实现。
- 电脑首版提供一种普通策略：按合法动作评估可达地点收益、可支付公园、热忱进度和季节奖励；同分按已保存局面的稳定候选顺序选择。合法性永远由规则核心决定，不由评分函数决定，策略不额外消费玩法随机。
- 教学用明确固定局面串联移动／天气、占位与营火、填水壶、购装备、预订与游览、热忱、季末及计分；另有露营替代、Teddy正反牌／两组顺序、单人阈值、志愿项目修改四组专题。每关目标与正常玩法差异明示，可跳过、重做本教学关；教学重做不迁入正式房间。
- 提示只指出合法目标及公开信息依据，不假装最优解；只在练习提供。可以打开完整图鉴，不显示即将抽到的牌。
- 本机自动存档覆盖正式确认的阶段、牌序、电脑待行动和版本；刷新恢复，不重抽。浏览器不允许保存时明确提示“本次未保存”。不把存储失败当成功。
- 练习进入后台／规则弹窗／设置／竖屏提示时暂停电脑；返回继续同一步。退出设置停止标志，浏览器返回不能悄悄让电脑继续。继续练习与重新开始分别提供。

### F10 全量图鉴和规则页

- 支持公园／装备／热忱／水壶／季节／地点／露营板正反面／Teddy正反关系／志愿项目／单人参考分类；搜索中英文名、筛选费用资源／效果，显示种类与副本数区别。正在生效的志愿项目及其改变的规则常有摘要入口。
- 每项有短文、详细效果、来源版次和数量。公园显示“63种，每种1张”，水壶按效果种类显示重复份数，不能把24枚说成24种。
- 规则页能从正在发生的步骤直接定位相应条款；公共说明不含内部接口和部署细节。图鉴／规则可竖屏阅读。
- 设计阶段未知或待裁定字段在设计资料里显式标明；将来运行版本必须完整，不能把“待补”卡混进随机牌库。

## 2. 动作与阶段的一一对应

以下为业务动作分解，用于核查功能覆盖；不是HTTP字段名或额外确认步骤。实际严格十类意图与字段冻结于[技术计划§4.3](../../plans/parks-v1.md#43-领域动作与提交边界)，多个已知条件由一个意图原子确认。共同前提：原参赛者／正确选择人、正确局／阶段、匹配修订及实体版本；失败拒绝且不改材料。每个正式选择保存后才进入下一步。

1. `moveHiker`：本人主动回合，选择在途棋子、前方地点、营火确认；一次原子确认棋子、目标、普通／露营分支及必要的帐篷、营位、外层支付，成功才固定移动和扣费。占位许可按移动前营火状态核对，不能借到达后装备点火取得进入资格；合法进入后可按新机会重新点火。普通天气／地点机会仅在同次确认选择普通分支时生成，露营仅生成既定营地内部动作。不能跳过目的地合法性。
2. `chooseSiteAction`：仅对具有多个基础选项的本次地点选择，生成唯一机会；公园预订与游览、照片与水壶的互斥分支不能两边都做。
3. `reservePark`：本次预订机会，选择公共槽或牌堆顶；公园去本人预订区，公共空位延后补。本次机会用完。
4. `visitPark`：本次游览机会尚未结束，选择公开或自己的预订牌和完整支付；付款／归属／即时效果同次保存，结清后可继续游览或结束这次机会。
5. `buyGear`：本次购买机会，选择展示槽或盲购及支付；支付成功才固定牌，触发／补市场遵守规则。免费不等于无购买机会也能拿。
6. `gainCanteen`：已有得壶机会，选择展示或堆顶及合法槽；填满处置依[D04](decisions.md#d04-满水壶槽和牌堆耗尽)。不是可以随时凭空新增壶。
7. `allocateNewWater`：拥有某次未分配新水，按本次数量选背包或未填行，产生该行所有既有水壶收益。单个新水不能既入背包又填行。
8. `takePhoto`：已有拍照机会，选择实际资源和合法增强；归还资源、照片变化、徽章／热忱触发一并记录，不能以动画完成回调发分。
9. `tradeResources`：有指定交换机会时才可选数量及资源，按该机会的兑换比例和不同类型条件结算；不存在全局随意交易。
10. `useGear`：可用的本件装备机会，核具体触发及本回合限次，保存费用／奖励／已用。不可再用本件追触发自身。
11. `choosePassionBranch`：目标已完成且没有分支，选择能力或计分；必选，保存后继续触发链。不把客户端显示进度当达标证据。
12. `resolveDie`：系统基于已存在掷骰机会固定六等概率结果；有选项才交玩家选择，不提供“重新掷”或浏览器随机。
13. `discardOverflow`：结束回合时背包超限，选足够数量归池；不能丢水壶内水来满足背包上限。
14. `finishTurn`：必做全部完成，确认放弃剩余可选机会，核容量、补公园市场，换合法行动者或进入季末。
15. `resolveSeason`：系统固定获奖者、按顺序发放奖励和待选择；单个步骤可恢复。每位奖励窗口结束补公园，再交下一位；全部完成后才重置季节材料或最终计分。
16. `chooseGainReplacement`：Botany／Rock Climbing等合法替换在领取前由拥有者选择，记录原领取、替换数量、使用标记和目标池；不是使用普通装备，也不是资源交换。拒绝／刷新不重复扣次数。
17. `chooseStartingPassion`：开局2选1时当前责任人从已固定候选中保留1张，确认后公开并保存，下一位选择；不允许重新抽取或改候选。
18. `chooseArrivalMode`／`chooseCampsite`：这是移动预览中的本机分支选择，不另作一个可以留下半次到达的提交。将普通／露营、帐篷、营位及外层费用一并交`moveHiker`原子确认，再分步执行营地内部动作；未选前不发普通天气／徽章／地点收益。
19. `chooseTeddyOrder`：官方单人由真人为已固定牌选择本批尚未处理的颜色组；同位置棋子按M01稳定编号自动选。不能借组别选择越权移动任意棋子、改变目标或重抽卡。
20. `advanceTeddy`：服务端／本机练习权威流程固定翻牌、正反关联、移动及具体清除结果，按一个自动步骤一个原子边界保存。所有结果确认后才给下一真人动作；这是自动规则，不是浏览器POST一个随意骰面。
21. `resolveVolunteerChoice`：仅实际志愿项目要求的选择由正确玩家完成，保存指定对象、费用、修改与下一步；没有选择的强制限制由规则自动执行，不要求玩家记住或手动遵守。
22. `finishOpportunity`：结束当前连续游览等机会，明确放弃该机会剩余可选次数；已有费用、项目义务及必选子机会须先结清。保存后不得重开同一机会，返回当前父机会／窗口，不等于`finishTurn`。季奖根机会全部结清后由系统核容量、补市场并交下一奖励责任人；具体提交字段见[技术计划](../../plans/parks-v1.md#43-领域动作与提交边界)。

对暂停／恢复／离场采用平台动作而非上述领域意图。查看、过滤、缩放、声音与主题不推进游戏revision。来自骰子／水壶／装备的额外机会带来源ID，不误用基础地点机会或复用两次。

## 3. 实施前检查与交付证据

- **内容**：全部实体有完整定义、份数、触发及出处；每一种行为能对应上述动作或明确新增动作。存在未知效果即不允许该版本开局。
- **规则**：全套卡库逐种数据校验，再按行为族和真实组合验证；无需为63张同结构公园手写63套同形测试，但每张费用／效果均与证据比对。
- **一整局**：基础2人／5人、双人Teddy＋露营、官方单人＋露营＋志愿项目从初始化到秋季终局，包含跳过已完成成员、季末中途恢复、计分分项；其余合法配置与冲突组合按交付清单验证。设计文件通过不代表完整局通过。
- **页面**：准备／本人／他人／观众／必选／季末／暂停／结果／教学／练习均检查元素、布局、操作，再做功能结合。至少覆盖六主题、短横屏、键盘和横竖往返。
- **权限恢复**：双账号＋双设备，错误角色、重复请求、旧revision、POST响应丢失、SSE重复、随机后重启、401与503；明确保存和投影边界。
- **发布**：[技术计划](../../plans/parks-v1.md)独立维护Step 0、规则、平台、页面、验证及发布进度。2026-10-11已有245项展示定义、6幅代表原创主体与隔离样板；尚无PARKS正式房间、可玩练习或引擎验收。本功能合同不是完成证明，现有六款的实际共通模块升级也不能移作PARKS装配通过。
