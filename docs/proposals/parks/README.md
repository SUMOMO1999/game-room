# PARKS 国家公园首版设计

状态：2026-10-11，**v0.4全模式规则基线已实现，正式页面、全量原创资源和12课教学已接入；最终制品与上线验收进行中**。用户本轮明确要求“原盒可选玩法也全部一起上线”，范围以 **PARKS Second Edition、官方规则书1.1：基础、露营、双人Teddy、官方单人及志愿项目**为准。基础146份材料已转录，新增模块的规则与材料见模式资料；原书未明示的项目解释单列。目录及设计审查不等于游戏、美术或整局测试完成。

阅读顺序：本页看共同基础；[模式规则](modes.md)看露营、Teddy与单人差异；[全量公园](parks-list.md)、[内容目录](content.md)及[可选模块材料](optional-components.md)看所有定义；[功能合同](functions.md)看页面与恢复；[边界解释](decisions.md)看非官方补充；[完整交付清单](release-scope.md)约束最终上线。百鬼商会继续等待实体资料，不被本提案替换。

## 1. 首版目标与范围

让朋友在一条逐季变化的步道上安排两个徒步者，收集资源、配置装备和水壶、游览公园及拍照，最后比总分。每次选择前进多远，都在权衡眼前收益、沿途机会及对手占位。

- **朋友房间：2～5人竞争；官方单人：1人加规则驱动的Teddy，均最多8位观众。** 二版共春、夏、秋三季；官方时长参考40～70分钟，不作为实测承诺。单人用得分等级，不把Teddy当需要账号或准备的人类玩家。
- **独立练习：本机官方单人、一个人对一位普通电脑及分步教学。** 普通电脑使用人类玩家规则与该电脑角色有权看到的信息；官方Ranger Teddy按专用卡驱动，两者不能互相替代。全部模式都能在图鉴和帮助中学习，保存／继续／重开／退出为必需项。
- 包含公园、装备、热忱、季节、水壶、天气、摄影徽章、营火和完整计分。不会用删掉未查明装备的方式冒充完整二版。
- **首发同时提供露营、双人Ranger Teddy、官方单人及全部9张志愿项目。** 志愿项目按原书可加到任意人数，露营可与这些模式组合。每局可关闭可选规则，不代表交付省略模块；不含不在本原盒的促销替画牌及一版扩展。
- 不增加交易、战斗、自由造卡、伙伴编辑规则或跨局经济；新增内容仍须经过逐项定义与实现。只记录本局原生分数及结果，不接 414 永久积分。
- 可以经平台暂停后分次继续；跨局不保留背包、装备、已游览公园或能力。

运行标识为 `parks`，规则包 `parks-2e-full-v1`，每局冻结模式与可选配置。实现与发布证据唯一维护在[技术计划](../../plans/parks-v1.md)；新建由现有服务的专用开关控制，沿用原主机与身份，不新增固定服务。

## 2. 新人先懂这五步

1. 轮到你，选自己尚未到终点的一名徒步者，向前选一个能执行动作的地点。
2. 看清地点、天气、占位与营火代价，确认移动。不能往回走；越过的地点不拿奖励。
3. 在这个地点拿资源、购买装备、拿水壶、拍照，或预订／游览公园。满足条件的装备和水壶可能带来后续收益。
4. 处理完本次选择与背包超限后结束回合；仍在路上的下一位玩家行动。两名徒步者都到终点，本季就休息。
5. 三季结束后，合计公园、照片与照片奖励、秋季奖励、热忱计分及先手标记的分数。

不是每回合把所有想做的事都做一遍：地点提供行动机会，装备和水壶提供明确的额外机会；有资源不等于随时可以买公园或装备。

## 3. 材料、区域与信息

完整组件数和目录状态只在[内容目录](content.md)维护，避免数量重复后漂移。`typeId` 表示一种定义，`copyId` 表示这一局的一份实体；图案、昵称、屏幕位置不能充当实体身份。

**公共区：** 中央步道与天气、全部徒步者、终点三个动作位；上方三个公园展示位、三个装备展示位、三个水壶展示位；当局春夏秋奖励、公共资源池、先手与摄影标记。启用时还包括当前露营板与帐篷、Teddy当前正反关联牌、志愿项目摘要。牌堆只显示背面与剩余数，未来牌序和随机状态不发给玩家或观众。弃除装备与已用季节有单独去向，不回填成可购买牌。

**个人区：** 背包、三行各两个槽位的水壶、营火、热忱、预订公园、已游览公园、装备与照片。背包基础上限为每回合结束最多12枚资源，启用志愿项目时按模式规则显示实际上限；本回合过程中可以暂时超过，不在每次获得资源时提前丢弃。水壶中的水与背包中的水分别计数。公园、装备与水壶不设未经规则依据的额外持有上限；水壶只有六个摆放槽，满槽行为按D04，不额外增加槽位。

个人已摆出区域、热忱开局目标及选定分支公开。对从顶牌预订的公园，本稿采用[D09建议](decisions.md#d09-预订公开)：确认后正面公开；原书未专门说明其可见性，保留此解释的证据边界。客户端选目标草稿、未确认支付方案与电脑内部评估不公开。

组件目录可以让人了解有哪些牌，但不能泄露本局下一张是什么。复原画面时只恢复当前账号有权看的区域；公开局面不等于允许匿名凭房号读取成员资料或聊天。

## 4. 开局与轮序

按官方规则书印刷页2～3布置，以下是共同基础。启用模块按[模式规则](modes.md)应用明确覆盖项，包括初始移出牌、营火、天气、容量、额外费用、获取限制和Teddy；不能先按基础发完材料再临时删改。基础数值没有隐式优先于志愿项目。

1. 固定参赛成员、座位顺序、规则／内容／资源版本及全部模式配置。每人选择一个可辨颜色与形状，获得两名徒步者、个人板、营火、一枚随机起始水壶；热忱可设每人随机1张或官方可选的2选1。2选1的候选先固定、各人私下选择后公开保留牌，弃选移出本局，不可重抽；选择完成才开始徒步。不凭空发初始背包资源。
2. 中央公园地点固定在步道第5位；8块地点板随机放其余8位，形成9个普通地点。不是8格，也不是把公园地点一并洗牌。基础模式不使用露营板面。
3. 从第二个地点开始放太阳、水交替的天气，基础开局共8枚（各4枚），包括固定公园地点；气候志愿项目按原位置去掉太阳，后续季节缺货按D11留空。掷六等概率步道骰确定摄影标记：山→山地点、森林→森林地点、太阳→双太阳、水→双水、野生动物→资源换野生动物、特殊面→水壶／照片地点。骰子在回合中的效果与定位用途分别定义，不能把随机面当屏幕坐标。
4. 分别洗公园、装备、水壶，公开各三个。春、夏、秋奖励分别抽一块并从开局公开；其余不入本局。
5. 起始营火：标准2～3人熄灭，4～5人点燃，官方单人亦熄灭；Teddy不算真人数。春季之后通常重新点燃，启用Leave No Trace时按项目每季熄灭；不把一版“到终点即重新点燃”带入二版。
6. **本项目建议**由服务器均匀随机选首位，其他人按冻结座位循环；官方“最近游览国家公园者优先”的线下选法不做个人旅行记录采集。此差异在准备室说明。

等待页常显六位房号、复制邀请、成员／观众、人数、规则摘要、准备和开始条件。改规则配置清准备；本稿不提供随意改季数、背包上限或卡数的开关。开始后新账号自动观战，原账号恢复原席位。

轮序展示由实际行动人和仍在本季路上的成员决定；Teddy插入时机、两个颜色的顺序与最后在途者按模式规则。已到终点的玩家显示“本季已完成”，不被标成下一位；先手标记用于下一季起始顺序，不能在本季中途拿到标记就立即插队。共通名单当前按完整循环推下一位，实施计划要核对这个差异，不能只调用现成排序函数就声称正确。

## 5. 一次回合怎样完成

领域流程为：**选择徒步者与地点 → 确认移动／营火 → 处理地点和相关收益 → 完成所有必选项 → 背包超限选择 → 结束回合 → 补市场／换人或季末**。所有玩家／系统动作逐项见[功能合同§2](functions.md#2-动作与阶段的一一对应)；机会必须来自地点或具体效果，不是持有资源就能随时买牌。

### 5.1 前进、占位与确认

- 选自己的一名在途徒步者，前进任意正数个地点；不能后退、原地停留、移动对手或移动本季已到终点的棋子。
- 目标必须能够执行其地点行动。免费得资源地点遇到空池及无合法前进时的终点出口采用[D04～D05建议](decisions.md#d04-满水壶槽和牌堆耗尽)，不将这些未明示的边界称作原版结论。
- 普通地点已被任何徒步者占据（含自己）时，必须有点燃的营火并将其熄灭，才可共享。终点动作位不限占用人数，不消耗营火。
- 点击棋子后突出合法目的地，非法目的地给具体原因。移动预览显示会消耗的营火、可领取天气、地点动作及其费用；再点明确“前往”确认。拖动只是可选输入，不作为唯一操作方式。
- 确认前可取消。确认后移动与已揭示随机结果不可撤销；没有“重来一次骰子”。后续选择属于同一正式回合，刷新继续原选择。

### 5.2 资源与天气

资源包括山、森林、太阳、水、野生动物。第一位到达带天气的地点者拿走该天气，同地后到者不重复拿。地点行动与天气的可选顺序要保留，不能强制先收天气而失去水壶组合机会。

野生动物可替代游览公园、买装备、拍照所需普通资源；公园明确要求野生动物时必须支付野生动物。不能用野生动物填水壶。有限资源池没有某项时不凭空生成、不记负库存；已支付的资源返回公共池。免费奖励取可取得部分；季末多人顺序采用[D08](decisions.md#d08-季末奖励窗口)。

### 5.3 公园行动

- 一次公园行动选择“预订一张”或“游览一张以上”，不能先预订再把同一个基础行动当成游览。
- 预订可选展示区一张或牌堆顶一张，移到自己预订区；其他玩家不能游览你的预订牌。
- 游览可从公共展示区及自己的预订区选择；先展示完整费用及实际支付，足额确认后资源回池、公园进已游览区，并处理即时奖励。
- 同一行动可以继续游览多张，先获得的即时奖励可支持后续游览。每张付款及结果分别确认保存，不能预先把整批费用一次扣完而漏掉中间收益。
- **公共公园在整个回合结束后才补位。** 本轮已拿走的空位保持空，不能马上抽新牌让本轮继续购买新牌。季末奖励按D08把每位获奖者的完整窗口作为对应补位边界，窗口内也不补。
- 即时奖励可能给资源、水壶、摄影徽章或掷骰；有选择时先进入明确待选择状态，不让下一位提前行动。

### 5.4 装备

获得一次购买装备机会时，买一张展示装备并支付其费用，或支付 2 太阳抽牌堆顶一张。购买后立刻归自己所有；展示位购买完成按规则右移、左补，不能与公园的延迟补位共用错误时机。

装备具有自己的触发条件，每件装备每回合至多使用一次。必须区分“停在某地点”与“获得某资源／执行某动作”，不能因图标相同就互相触发。新买装备立即可用；不重放已经结清的动作，地点型与动作型的新购适用边界采用[D02](decisions.md#d02-新能力不重放旧动作)。

规则书正文与速查页对装备、地点行动排序表述有差异；本稿明确建议依速查页允许排列已经合法的机会，仍尊重费用／触发的因果顺序，见[D01](decisions.md#d01-合法机会与结算顺序)。这项选择是可审阅的项目解释，不是已取得的官方勘误。

### 5.5 水壶

获得水壶时可拿公开三枚之一，或拿堆顶一枚，放到个人板空槽；拿展示水壶后立即补位。三行每行最多两枚，共六槽；满槽／无可取水壶依[D04](decisions.md#d04-满水壶槽和牌堆耗尽)，不能无声增加第七槽。

每当获得新的水，可选择进背包或填入尚未使用的一行水壶，获得该行已有两枚（或一枚）水壶的收益。已放进背包的水不能日后拿来填；一行每季填一次。给本季已经填过的行再添水壶，不补发新水壶收益。季末水回公共池，行状态归零。

页面必须明确显示“刚获得、待分配的水”“背包水”“本季已填的行”。多个新水、多个行效果或效果再生水时分步保存选择，不能从总水数推导触发次数。

### 5.6 照片、摄影徽章与热忱

一次拍照花一枚资源，得一张照片，照片值 1 分；5 张换一本相册仅是计数表示，仍值 5 分。到摄影标记所在地点时拿摄影徽章，若在别人处则转移；地图上的摄影标记不随徽章转移。

持徽章者拍照时，每回合可多付一枚资源再拍一张。热忱完成条件、能力分支和计分分支见[十种热忱定义](content.md#3-十种热忱的规则定义)。完成条件后当回合立即选一个分支；选择不可反复更换，不能同时获得两路收益。持续减免、触发型能力限次及Wildlife和徽章的组合采用[D03](decisions.md#d03-热忱能力的限次与替换)。

### 5.7 终点与最后在途者

终点有公园、拍照、买装备三个动作位，可以多人同位。每季最先占对应奖励位者分别获得先手标记、野生动物、太阳。奖励与动作的顺序要支持先拿奖励再支付动作的合法组合。

两名棋子均到终点的玩家停止本季回合。只剩一个玩家仍有在途棋子时，其余棋子必须直接去终点，不能独自在中间反复收集。**每个棋子各占一个独立回合**：第一棋子去终点、做动作、核背包并补市场；再开始第二棋子的回合，重置本回合限次。官方印刷页12的例子已核清这一点。

## 6. 季末与最终结算

春、夏季：结算当季奖励 → 处理奖励引出的选择／随机 → 回收未领取天气、水壶清空、按配置重置营火、徒步者回起点 → 重新布置地点、天气和摄影标记 → 装备市场最右牌移出、其余右移并补一张 → 当前先手开始下一季。露营同步归还帐篷、揭下一板，Teddy同步收回棋子并洗其21张专用牌；详细顺序见模式规则。天气不足按D11，不挪用玩家资源补足。

春季奖励按当局季节块，四种夏季奖励均为两次步道骰收益，秋季按已游览公园的相应条件给 3 分；各季必须至少满足一次要求才有资格，符合的并列者均获奖励。每块的比较量、奖励及季末触发仍以完整内容定义为准，不能把12块都简化成同一效果。

秋季结束后不重置并多发新一季收益。总分由：秋季奖励＋已游览公园印刷分＋照片数＋照片排名奖励＋所选热忱计分＋先手标记 1 分构成。双人照片第一奖励 3 分；3～5 人第一 4 分、第二 2 分。原书没有写明照片并列，本稿提供[D07确定建议与例子](decisions.md#d07-照片并列)：正数才有资格，同分同名次、占名次跳位、对应名次奖励全给。季末窗口与顺序采用D08，照片标记不足采用D06的整数计数。

总分最高者胜；总分相同则比较已游览公园数量，仍同则共同获胜。剩余资源和未游览预订牌不擅自加分。结算页列每个分项、并列依据和原参赛成员，允许查看自己的及公开已结算内容，再来一局先回准备室。

以上比较奖励适用于多人。官方单人季节资格用春3／夏4／秋5的阈值，最终没有照片名次奖励，不给Teddy计算竞争分数；显示个人总分、徒步等级与志愿难度。露营可能消费照片，所有照片分、排名与Wildlife计分均读当前净持有量，不能读历史拍摄累计。

## 7. 手机横屏与桌面交互

沿用[房间布局规范](../../design/room-layout.md)，不是按实体桌布照片等比缩小。**路线是中央主区，公共市场靠近路线，个人行囊在下方，侧栏提供成员与当前步骤。** 公园风景用于阅读和氛围，不牺牲费用、动作与选中反馈。

- 宽桌面：左侧成员／季节摘要，中间路线和公园展示，右侧当前动作详情；下方个人资源、水壶与装备。多余横向空间给卡牌详情和个人区，不放空白大块，也不把路线拉得难以比较。
- 短横屏设计基线 667×375 CSS px（按实际安全区和可见高度再量）：保留44px房间工具栏、中央路线与目标、紧凑个人资源行、当前确认／取消。市场及个人装备用明确标签切换查看，同一时刻只展开一个详情区；当前费用和确认不能需要先关掉另一层才看得到。
- 路线地点点击目标至少44×44，编号、主要动作和占位状态常显。9个普通地点（含固定中央公园）若无法在安全宽度内清楚排完，改为两行连续编号和连接箭头，逻辑次序仍固定，不缩成小点。
- 公园概要卡拟定最小宽104px，费用／分数字号至少14px；不足时用带“第几张／共几张”的分页和44px翻页键。详情展开宽度按视口，文字至少16px。此处为待Step 0实测的设计指标，不是已通过的像素结论。
- 自己背包五类数量、当前容量（基础12，受项目修正时显示依据）、水壶已用行和当前营火始终有摘要；装备及已游览公园多时使用可打开的列表。启用露营时营位和帐篷状态可直接查选；Teddy步骤和当前志愿限制不能藏在纯规则页。选中某物件后保留稳定编号，不因为列表重排改变目标。
- 竖屏显示转横屏提示、房间状态及聊天→设置→退出；不执行整页CSS旋转，不要求系统支持锁方向。转横→竖→横保留已确认阶段与合法本机选择，服务端期限继续按房间规则计算。规则／资源图鉴可以竖屏阅读。
- 移动选中、合法目标、支付不足、待处理效果、别人最近公开动作使用不同描边、图标和短句；颜色之外有形状／文字。每个选择步骤显示“还需选择什么”“做完会怎样”。
- “取消选择”只撤本机未确认输入；不使用含义模糊的“重做”。确认游览、买装备、盲抽前显示实际费用和不可撤回后果。
- 六主题只变界面背景、控件与文字，资源五种语义和插画保持；图片失败显示公园名、费用、分数、效果，不显示空白卡或共用笑脸。

## 8. 共通能力和本游戏差异

下列均为**待实施的真实接入合同**，不是“已复用”的完成声明。模块路径已核存在，详细接口审查留到技术计划。

- **房间与轮序**：房间平台管理成员、准备／房主、暂停、稳定席位和结果；游戏只给本季合法行动序与原生得分。两入口使用同一套房间数据；新增游戏不修改账号或登录客户端。
- **聊天与通知**：正式房间用 `app/room-chat.mjs` 的实际骨架及挂载，准备／进行／暂停／结算和观众均可聊天。房间栏右侧紧凑排列聊天→设置→退出。气泡锚点有真实尺寸，自己发言显示确认；键盘打开保留输入、发送和关闭，不压住已输入文字。
- **设置／六主题**：`app/platform/room-settings.mjs`、`game-theme.mjs` 与共通几何样式；声音、规则、主题和房间安排入设置。准备／主屏／结算／练习均须实际展开验收，不只测标题栏。
- **音效**：`room-audio-controls.mjs` 与 `app/game-audio.mjs` 管手势启声、音量和去重。移动、收资源、购入、拍照、轮到自己、聊天、季末与胜负各有语义；复合链节流，POST/SSE同事件只播一次，恢复不补播历史。没有声音仍有可读反馈。
- **时间与暂停**：每个完整主动回合、初始热忱选择、季末奖励窗口及独立Teddy人工选择批次各30分钟，子选择不续满；到时保存并暂停。超时只能由本次责任人继续并获得新的30分钟；普通暂停沿平台“全体真人同意、任一真人恢复”并沿用剩余时间。普通房间有效业务后8小时、暂停后7天的保留期及权限细节只以[功能合同F07](functions.md#f07-暂停离席和恢复)为准；练习无强制倒计时。自动步骤由服务端推进，不靠客户端动画回调。上述超时差异需真实适配，不是假称已有支持。
- **离席**：返回大厅保留席位；明确退出房间在进行中中止本局且不计输赢；观众退出不改游戏。全体离线不等于退房，沿用平台保留／回收策略。退出确认说明后果，未知游戏提交期间仍有独立退出入口。
- **恢复**：沿用 `room-client.mjs`、`platform/room-session.mjs` 和动作意图工具。断流保留最近可展示局面，焦点切换不整页loading；401遮私有内容并提供重登，503保留可恢复进度，不写成退房。随机或扣费结果未知先查原回执，不能补发新的随机动作。
- **观众**：可看经成员权限投影的公开区域、阶段与动作记录；没有任何代操作权，不获取未来牌序。观众不参与准备、暂停同意或结算排名。
- **练习**：使用相同规则定义与页面呈现，复用设置、主题、声音、`practice-navigation.mjs`，不显示假房号／联网聊天。存档只在本机，成功后提示；不可写时说明当次练习。关闭、刷新和弹窗暂停电脑动作，重进继续同牌序和待选择；明确退出后浏览器返回不偷偷重启电脑计时。

## 9. 权威状态、选择与保存

规则模块决定合法移动、费用、触发、换季和分数；服务端适配器决定配置、公私投影、权限、期限、快照校验和历史。内容定义是不可变目录；页面只消费投影并提交意图，不运行朋友上传的任意效果脚本。

建议的持久状态包括：`matchId`、规则／内容／资源bundle、冻结参赛席位、季节及回合序号、当前行动者、两棋子位置、地点／天气、三个市场与牌序、资源池、各玩家公开区域、每装备本回合已用标记、水壶本季状态、季节奖励处理顺序、先手和摄影徽章、待选择、期限及最终结果。存档schema与规则版本独立，版本号须技术计划核对现有schema后再分配。

全模式还须保存：冻结开关和志愿项目、热忱候选及选择顺序、3季露营板及面向／营位占用／帐篷位置、21张Teddy牌完整正反配对与牌序／弃牌／当前两卡关系、Teddy颜色与棋子、当前执行批次与负责选择人、志愿修改的容量／限制／已触发标记、照片消费和实际装备购买计数。禁令、费用、替换、获取及容量检查的顺序依模式规则，不能由页面各自实现。

每次动作都带原意图编号、预期修订、对局和选择编号；服务器检查成员／角色／当前阶段／可用材料后，将付款、资源或牌区移动、固定随机、下一选择、回执与新revision一起保存，成功后才广播。一次骰子或盲抽成功后，刷新／换设备仍是同一结果；双设备同时选不同分支只能有一次成功。

`pendingChoice` 必须记录选谁、从哪里选、数量、已付费用、固定结果、合法选项依据和下一阶段。公共日志不放未来牌序、其他人的未公开候选或内部身份键。选择等待属于业务状态，浏览器关闭不丢；hover、放大、详情页和未提交支付组合只属本机，不写公共牌桌布局。

有限资源守恒按每种资源分别核对：公共池＋天气＋背包＋水壶内水＋已领取待分配 = 固定总数。每份牌或水壶仅在牌堆、展示、个人区域、移出区之一；临时展示不能多出一份实体。照片与相册保留等价计数，不把换相册当奖励新增5分。材料或关键定义缺失时阻止开局，不能抽到未知卡才临时解释。

正式局与练习局都固定内容版本；新素材或新定义不重解释旧局。恢复要在独立目录和新进程验证，各中间选择与季末半途均可继续；备份不恢复登录会话。读不到旧bundle时明确停止并给恢复出口，不清库、不降级成别的游戏。

## 10. 边界例子与验收设计

以下是设计阶段制定的**验收用例**；已执行的领域、平台及页面证据在[技术实施计划](../../plans/parks-v1.md)维护，不能把本页清单本身当运行结果。正式验收保留完整初始材料、动作序列和结果。核心规则、持久存储、实际HTTP/SSE、浏览器、真机分别记录，不用总测试数相互替代。

1. **跳过与占位**：甲棋子在1，目标4空、2/3有天气；前往4不拿2/3。4有自己的另一棋子也需营火；熄火则拒绝且所有状态不变。观众或乙不能替甲确认。
2. **即时奖励连游览**：甲有3太阳、1森林、2水，已预订Everglades，公区有Joshua Tree。甲在公园行动先付3太阳＋1森林游览Joshua Tree，得2水；再付4水游览Everglades。两公园各3分、背包归零，公区到回合结束才补。来自官方例子，三张相关公园的费用与奖励已在全量目录交叉核验。
3. **水壶与容量**：甲背包12枚，获得2水，允许分配至未用水壶行或背包，并继续合法消费；只有结束回合仍超12时要求选弃。水已经进背包后不能再点“填水壶”。有水的行新加一枚水壶不立即发奖励。
4. **限次与再触发**：效果获水→填壶→拍照→装备得水，已用过的同一装备不能再次触发；另一件合法装备是否可接续按其独立定义检查。不能用“获得2太阳”等同“停在太阳地点”。
5. **中途能力选择**：达到热忱目标后显示两分支、后果和确认；选能力后本回合后续合法事件可受益，但不补算过去事件。选计分后不同时享受能力。
6. **随机后的恢复**：确认购买牌堆顶装备后断线，另设备恢复同牌、同费用和同一后续选择；重复原请求不再抽，换正文拒绝。
7. **季末处理**：两位季节奖励并列，处理其中一人的随机后重启；依D08已固定赢家及顺序恢复，只处理余项，不重掷、不把所有营火/水壶提前重置。剩一枚森林时前一位得到、后一位缺货，不重新改判赢家。
8. **轮序与结束**：多人中两名玩家已到终点，侧栏下一位跳过他们；先手标记转移不改变本季循环。末季无第四季；同分先比已游览公园数，再同为共同胜利。
9. **超时与离场**：超时和本人选择同时提交，只有一种正式结果；已扣费待选保留。玩家明确离席按中止收口，无额外季末奖励；观众退出不动局。普通暂停恢复不重给时间。
10. **完整局门槛**：固定牌序完成2人和5人三季完整局，逐事件记录资源／牌区／限次与终局分项；核心数据齐备前此项保持待验，不拿手写几步示例充当整局证明。
11. **基础画面先验**：等待、自己回合、他人回合、观战、待选择、季末、结果、暂停及练习，分别核房号或练习声明、动作、设置、聊天与退出。667×375、844×390、1024×768、1440×900及横竖往返；大装备列表、最长卡名、五玩家长昵称、六主题、聊天键盘分别组合实看。
12. **真实入口与旧游戏**：两独立入口的资源路径、匿名不可读房间、同名两成员/跨设备/观众投影、正式与练习入口和返回历史、新进程恢复；新增适配若改共通流程，回归受影响旧五款。手机实际触摸、系统音频和安装模式单列。

13. **全模式与组合**：在标准2～5人、双人Teddy、官方单人六类上分别验证露营开／关和0～4项目配置；完整局至少覆盖基础2人、基础5人、双人Teddy＋露营、官方单人＋露营＋项目。四板八面32营位、21张Teddy正反配对及9项目逐项核行为，另以[模式规则](modes.md)的用例覆盖冲突组合；60类配置覆盖不冒充全部牌序穷举。
14. **不可卡死与恢复**：保留必需基础费用、空池天气、营地付照片、项目降容量、禁止照片与免费奖励、只可游览预订牌、额外碳费用分别有确定出口；Teddy翻牌后和两颜色之间、热忱选一半、露营付费后刷新恢复同结果。

## 11. Step 0资源方向

先评审技术实施计划，再进入Step 0。选择原创旅行手册风格：自然插画、简洁费用条、明显资源形状、克制纹理。所有数值和规则文字由数据与排版呈现，不让AI把费用、字或图标画进插画里。

样板需同时包含：普通／有即时奖励／费用含野生动物的公园、长名公园、地点触发与动作触发的两件装备、双分支热忱、单／双水壶、占位地点、空池、禁用目标和缺图替代；新增模块取一整块双面露营板、帐篷、两张有正反关联的Teddy牌、一张会改变容量的志愿项目及单人结算。用真实定义展开准备室、主屏、设置、聊天和结果；代表样板通过才完成Step 0，不先批量生成全部插画。

全量采用63幅对应实际地点的自制或许可明确风景；装备主体按13种名称制作、分别排37种规则牌；37个实体不等于37幅独特插画。水壶、季节、路线、资源以及全部露营面／Teddy正反／志愿项目使用统一图标和数据排版，数量依两份目录逐项验收；不把每个规则变体变成独立AI插画任务。官方卡图只作查证，不放进应用或公开仓库。全量资源完整且可识别才允许完整接入／发布；当前245项定义均有可展示资源；63公园风景与13装备主体已经制作，15个全图／15个缩略图已解码并逐项核映射。Step 0过程作为历史保留，实际美术与许可见[资源清单](../../assets/parks-v1.md)。

## 12. 最终RV结论与剩余门槛

**已知材料分组与玩法歧义已形成有来源、有版本的设计选择；没有需要用户凭玩法经验补答的事项。** 基础、露营、双人Teddy、官方单人、全部9志愿项目及合法组合都进入同一最终交付范围，练习、图鉴、共通房间功能没有另拆到以后。核验结果保存在[设计检查记录](design-checks.json)。

这轮实际修正：

- 原稿排除可选模块与用户最终目标冲突，现统一为[全模式交付清单](release-scope.md)的11项必交模块；补热忱2选1、项目多人适用及60类配置覆盖。
- 基础费用可能被额外拍照先花光、之后无法完成地点动作：D01保留确定支付方案；项目强制后果也纳入检查。
- 换季遗漏旧天气回收及资源不足的出口：D11明确回收／缺货留空，不能补造资源。
- 普通暂停与超时恢复权限冲突、正式单人误当本机练习：F07统一平台合同，超时例外、保留期和负责选择人分别写清。
- 房间取消准备、角色切换、房主交接、中止回准备、最后真人离席，以及教学真实入口补入F02/F06/F09。
- Teddy同位置自动选择、单人颜色选择、两张牌的配对与轮序、露营同次移动确认等多份资料统一；普通电脑能读自己的私有热忱候选，不能只给公开投影导致卡住。
