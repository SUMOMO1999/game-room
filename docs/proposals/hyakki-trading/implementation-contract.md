- `app/game-registry.mjs`、`server/games/adapter-contract.mjs`已有按游戏隔离的动作、公私投影、时钟和生命周期入口；`app/rooms.mjs`拥有成员、准备和房间状态。本游戏规则不得导入账号或其他游戏规则。
- `app/rooms.mjs`的可选`lifecycleTransition`用`terminal:false`保留原局；终态`status`明确completed／aborted，不把认输统一记无输赢。缺省旧适配器行为不变，未知状态组合拒绝。仅`checkpointOnly`变化不得清暂停投票、写活动或续房间活跃时间。
- `server/durable-rooms.mjs`的`usesPresenceLifecycle`先核可信席位在线再推进经济动作／超时，提交受presence版本和最早有效租约守卫；playing与paused均处理业务截止。`presence/server-recovery/capacity`是可信服务器原因，只有内部`applyLifecycle(...capacity-cleared)`能申请解除容量限制。
- `gameClock`只需投影当前可运行期限；主动剩余与对方回应时间由游戏状态统一保存，暂停/挂起不新造一套可独立写的截止点。绝不能直接开启“启动即取消”的旧恢复钩子。
- `server/room-score-commit.mjs`在积分／非积分分支前均核`maxSnapshotBytes`。受信任启动参数`transitionPreparers`限定scope，由old/new投影事件，与room、回执、计量同一事务保存；调用方不能直接传额外写集。tombstone必须由原冻结比赛和新增可信终局摘要构造末组，不能因为`next.snapshot=null`跳过收尾。
- 不新增Agora客户端、身份缓存、云资源或通用卡牌脚本平台。身份、原网址和挂载入口沿现有协议；只有需要修改共同协议或共享容量时再协调Agora。

## 3. 动作与提交合同

沿现有房间通道，仅新增本游戏动作：

- `peek`、`keep-peek`、`discard-peek`、`finish-draw`、`end-turn`：只当前玩家及对应阶段；留/弃绑定原pending对象，不由客户端提交牌面。`finish-draw`不能跳过未决peek。
- `buy/sell`、`play-character`、`buy-stall`、`install-tool`、`activate-tool`：本人合法持有/控制，显式牌引用、买卖方式与所需公开目标；银两、价格、收益和行动增量由规则算。
- `respond/decline-response`、`choose-effect`、`bid/pass-bid`：只当前decision的指定席位；白名单选择值或已获授权候选引用，带`effectId/decisionId`，旧窗口拒绝。借用是M08内部选择，不对客户端暴露可任意调用的“执行任意工具效果”。
- `resign`、暂停和继续由共通房间入口协调；不从客户端接收“对手已离线”“我已超时”等系统断言。后台/关闭标签不发送认输。

信封包含原`requestId`、预期修订、`matchId/turnId`，需要时加`effectId/decisionId`；请求正文不可变。身份、当前席位、动作归属、阶段、期限和原材料都校验后，单次事务保存房间、权威随机结果、回执及对应事件；成功再广播。失败不扣款/耗步。并发冲突只按原意图重新核查或拒绝，不把“买A”悄悄改成“买B”。

错误至少区分无权限、过期决策、状态已变、阶段不符、行动不足、钱/货/容量不足、目标不存在、版本不支持、存储繁忙；错误只提供调用者有权知道的材料，不能用“牌堆没有货物牌”拒绝貔貅袋泄密。

POST结果未知先按原请求查回执/当前状态；只有同编号同正文重试，不能重置随机种子、重新抽牌或扩大作用对象。SSE断线只同步当前合法投影，不重放旧动作。

## 4. 时钟、离线与终局的持久合同

主动30分钟、对方选择60秒；自己选择用主动余时，对方选择暂挂主动钟。`gameClock`投影一个当前期限，所有成本已确认但仍待选的步骤可跨设备继续。所有期限在实际写入时再次校验。

系统在线判断以稳定席位为单位，任何一个有效本人设备在线即在线。确认一席离线时，保存挂起原因、各钟剩余与`absenceDeadline`；不把token或连接租约本身写入业务备份。业务截止的起点来自已持久化的可信时间点；服务器重启/读备份不把它重设成“现在+30分钟”。实现时须用真实进程崩溃和presence丢失反例证明这一点，不能只模拟正常disconnect事件。

共同手动暂停保存独立的7天截止，暂停后自然离线不另启30分钟；先意外断线则保留原30分钟截止，不能用单人暂停覆盖。双方回桌解除意外挂起后才可共同手动暂停。只有有效双方回桌后才允许解除系统挂起；手动暂停仍需明确继续。过期业务截止在paused/挂起状态也处理，不能只轮询playing。

认输终局与意外断线取消分别记录；已完成交易不撤回，未成交预留释放，未完成区只读封存，禁止自动生成最后收益。冻结参赛名单保留作结果身份，当前成员退出不能导致历史只剩一个人。财富结算只用于正常收市，认输结果不依余额，无本游戏永久积分变动。

S1持久字段为`timing.active`（id/actorId/remainingMs/deadlineAt）、可空`timing.decision`（另含label），以及`lifecycle.startedAt/checkpoints/absence/manual/capacity`。checkpoint只存playerId及可信lastSeenAt/leaseExpiresAt时间，不存连接ID／token，不恢复transport lease。presence采样时间允许早于当前服务器时间，仍须逐席验证lease有效；不能要求两次Date.now完全相等。absence与manual各存一次startedAt/deadlineAt，capacity可叠加但不能擦掉它们。v4公开钟白名单只输出kind/id/deadlineAt/remainingMs/paused/label及matchId。

## 5. 记录、容量、版本与回退

当前业务状态固定110张及有限货物，不把整局公开事件无限塞进快照。完整公共历史与房间近期活动、动作回执、最终战绩分别承担职责：拟使用本游戏独立分页事件scope，服务端逐请求按房间/比赛权限投影，私人抽到什么不入公开事件。

阶段1冻结实际schema和scope编号前，重读当前注册表／备份清单，避免与PARKS或其他并行工作冲突；旧五款不清库不改身份。新格式同时补导入、恢复、备份和引用校验。禁止创建新局与允许恢复已存在局分开配置；发布前先准备能读新格式但不开放创建的回退包。

S1核定schema12、18scope（旧16scope保持可读），新增`hyakki-events`和`hyakki-event-meta`。公开事件每组单调sequence与room的`game.publicEventSequence`一致；严格词汇白名单不保存私看牌。group、match head和quota计量皆为加密记录，物理保留不依赖TTL误删；终局业务保留180天后分批原子回收。备份核record key、phase、冻结参与者、规则／内容版本、序号、结束时刻、实际字节和预留；恢复不含sessions/transactions/room-presence。具体限额与本次实测见唯一计划§11。

写入前必须从积分和非积分两条真实路径验证快照／事件大小与事务guard；普通事件预算与有界收尾预留分开：配额满时原子挂起并禁新经济动作，认输／取消／释放预留仍有落库空间；预算释放后才能继续。实际磁盘不可写则保留原确认状态、返回未确认或只读，不伪称落库成功。不得静默丢历史。确切存储限额在阶段1按110牌全部进手、多人观战和长局事件测量后冻结，不把自定量值当新玩法回合上限。

容量失败可能首先发生在presence／启动恢复，而非玩家操作；这些入口也须从原before、同份可信在线证据进入一次reserve挂起。迟到发现离线先按实际absence起点冻结，再设置capacity，不能扣掉检测延迟。已处capacity时内部absence/checkpoint更新不追加公开组、不重复消耗预留；只有正常预算可重新取得完整预留后才允许resume。reserve写失败原样报错，CAS重试有界。

只测有限负载：110张最密手牌、两玩家＋平台允许的观众、两设备竞争、20分钟代表交互轨迹；身份/SSE预算按当前共享服务准入核算。最多两轮针对性调优，正确性/隐私通过后，不为自定延迟目标无限优化。若需扩大基础资源/费用另行量化，不因本计划自行变更。
