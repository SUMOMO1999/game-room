## 3. 动作与提交合同

沿现有房间通道，仅新增本游戏动作：

- `peek`、`keep-peek`、`discard-peek`、`finish-draw`、`end-turn`：只当前玩家及对应阶段；留/弃绑定原pending对象，不由客户端提交牌面。`finish-draw`不能跳过未决peek。
- `buy/sell`、`play-character`、`buy-stall`、`install-tool`、`activate-tool`：本人合法持有/控制，显式牌引用、买卖方式与所需公开目标；银两、价格、收益和行动增量由规则算。
- `respond/decline-response`、`choose-effect`、`bid/pass-bid`：只当前decision的指定席位；白名单选择值或已获授权候选引用，带`effectId/decisionId`，旧窗口拒绝。借用是M08内部选择，不对客户端暴露可任意调用的“执行任意工具效果”。
- `resign`、暂停和继续由共通房间入口协调；不从客户端接收“对手已离线”“我已超时”等系统断言。后台/关闭标签不发送认输。

信封包含原`requestId`、预期修订、`matchId/turnId`，需要时加`effectId/decisionId`；请求正文不可变。身份、当前席位、动作归属、阶段、期限和原材料都校验后，单次事务保存房间、权威随机结果、回执及对应事件；成功再广播。失败不扣款/耗步。并发冲突只按原意图重新核查或拒绝，不把“买A”悄悄改成“买B”。

错误至少区分无权限、过期决策、状态已变、阶段不符、行动不足、钱/货/容量不足、目标不存在、版本不支持、存储繁忙；错误只提供调用者有权知道的材料，不能用“牌堆没有货物牌”拒绝貔貅袋泄密。

POST结果未知先按原请求查回执/当前状态；只有同编号同正文重试，不能重置随机种子、重新抽牌或扩大作用对象。SSE断线只同步当前合法投影，不重放旧动作。

## 4. 时钟、离线与终局的持久合同

主动30分钟、对方选择60秒；自己选择用主动余时，对方选择暂挂主动钟。`gameClock`投影一个当前期限，所有成本已确认但仍待选的步骤可跨设备继续。所有期限在实际写入时再次校验。

系统在线判断以稳定席位为单位，任何一个有效本人设备在线即在线。确认一席离线时，保存挂起原因、各钟剩余与`absenceDeadline`；不把token或连接租约本身写入业务备份。业务截止的起点来自已持久化的可信时间点；服务器重启/读备份不把它重设成“现在+30分钟”。实现时须用真实进程崩溃和presence丢失反例证明这一点，不能只模拟正常disconnect事件。

共同手动暂停保存独立的7天截止，暂停后自然离线不另启30分钟；先意外断线则保留原30分钟截止，不能用单人暂停覆盖。双方回桌解除意外挂起后才可共同手动暂停。只有有效双方回桌后才允许解除系统挂起；手动暂停仍需明确继续。过期业务截止在paused/挂起状态也处理，不能只轮询playing。

认输终局与意外断线取消分别记录；已完成交易不撤回，未成交预留释放，未完成区只读封存，禁止自动生成最后收益。冻结参赛名单保留作结果身份，当前成员退出不能导致历史只剩一个人。财富结算只用于正常收市，认输结果不依余额，无本游戏永久积分变动。

S1持久字段为`timing.active`（id/actorId/remainingMs/deadlineAt）、可空`timing.decision`（另含label），以及`lifecycle.startedAt/checkpoints/absence/manual/capacity`。checkpoint只存playerId及可信lastSeenAt/leaseExpiresAt时间，不存连接ID／token，不恢复transport lease。presence采样时间允许早于当前服务器时间，仍须逐席验证lease有效；不能要求两次Date.now完全相等。absence与manual各存一次startedAt/deadlineAt，capacity可叠加但不能擦掉它们。v4公开钟白名单只输出kind/id/deadlineAt/remainingMs/paused/label及matchId。

空间主张：**其他商铺在桌面上沿，公共货摊与本人货物在右侧上下相邻，当前牌及决策在中央，自己的艺术手牌与装备在下方。** 剩余空间属于放牌和阅读的桌面，不能自动分给牌堆按钮或单件装备。以下尺寸是构图约束，实际完成范围与验证只记[计划§11](../../plans/hyakki-trading-v1.md#11-当前进度证据与下一步)。

- **实体尺寸**：桌面牌堆按80～96px宽及纸牌比例呈现，不随桌面高度增长；两人对手商铺以约320～420px的内容宽度组织，装备使用定宽小牌，不均分空列。空装备区保留简短说明与真实放置出口，不画与满牌区域等量的大框。
- **完整决策组**：选中牌、目标、交易条件、最终金额／行动成本和执行按钮放在同组；当前行动条与该组相邻。必摸第一张的开局把摸牌入口和行动消耗连在一起，正在看的牌与留弃按钮同组呈现。紧凑交易区直接展示整组货物种类及数量，不能仅显示牌号；选中手牌状态可辨。规则和详情保留独立出口，不将执行按钮藏在长牌文末尾；金额沿当前合法投影与既有规则计算，不根据截图的显示值猜价格。
- **多人空间**：宽屏以固定席位轮序排列其他商铺，姓名、轮次、银两及手牌数稳定可扫读。六人不能复制五条全宽对手区；短横屏保留所有席位和行动／回应标记，明确选择某人后展开其货物与装备。需要针对对手作决定时，相关公开材料和确认必须同组可读；不因收纳隐藏唯一目标出口。选择只属本机草稿，确认前按当前投影重新核合法性，不读取对手私牌。
- **表面与字级**：绿底桌布为共享背景，纸牌为主要实体，货物区和商铺靠归属与距离区分；当前选牌／目标用状态强调，不靠每层新增边框。牌名与操作承担主字级，金额和计数用等宽数字稳定对齐，说明与编号次之；短屏不能以缩到难辨的装备名／已用状态换取精致。公共与个人货物保持相同图标尺度和顺序，个人区以归属标题区分。
- **保持的合同**：本人连续手牌不分页、不替换为文字摘要；已装道具独立且可辨朝向；桌游横屏、44px主要触控目标、统一设置及已有主题继续沿用。观战与练习共享同一构图方法，秘密投影、牌序、库存和收费不因布局改变。

构图验收使用两人／六人实际内容样板，覆盖稀疏开局、选牌交易及密集手牌／装备。先缩小看主次，再按真实大小看牌名、金额、状态和操作，最后完成一次“看到对象→理解代价→确认→看到结果”的真实操作。高度预算包含标题、席位、内边距和内容行，检查关键子内容确实位于归属容器。几何、构图与交互分别记结论；只修最影响决策的2～3项并复看，有新问题才扩大。只读满员样板与真实双人流程分开，不以样板证明多人规则完成。

## 9. 多人语义补全（建议与未决项，尚未冻结）

2～6人是用户已确认的产品范围；以下是现行实体双人规则的最小扩展建议，不能当作官方多人规则或已经验收的实现。

- **保留材料与基本流程**：仍是51种／110张、每人20两／5张手牌、首次普通摸看必做、取牌与用牌共用可调行动额度、六类各8件可调、全局5块扩摊板。人数增加不复制任何公共资源。开局固定席位轮序与先手，重连不重排，目标／回应／分配绑定稳定身份。
- **配对目标建议**：写“对手／双方”的牌选一名对手，其双边结果只影响使用者与该目标。需定目标的实际牌为C01、C08弃牌分支、M01／M04／M07／M08、T02／T04；M02手牌、M03留道具、M05货物和M06道具重分建议同样只影响这一对。尤其M05现行收集循环遍历所有玩家，不能只扩大人数校验后继续使用。
- **反制与嵌套**：建议只由受影响目标免费出锦衣卫，不让无关席位代反制；此资格仍须冻结。术士M08的拆道具目标与借用T02／T04时的目标分别保存，需明确借用时能否选择第三人，不能用一个目标字段覆盖两个步骤。持久状态须保存目标及阶段，不凭选中面板恢复。
- **全桌拍卖建议**：C09牙郎、C12花魁让全部有效参赛者依固定顺位竞价，跳过最高报价者和已放弃者；只剩最高报价者才成交，无人报价才流拍。当前“一人放弃就成交”只适用于双人，竞争报价、超时及离席必须按同一代际裁决。
- **番商未决**：多人可能同时持有番商，需要一套固定取牌优先权。建议按交易者之后的席位轮序处理，但不能因暗手是否有番商而选择性省略公开窗口；资格、总回应时限与逐席选择规则一起定，不能静默增加至五个60秒等待窗口。
- **收市建议**：在回合末达到60两后完成触发时的当前整轮，不给已行动者新增一轮。例如A→B→C→D，B触发只补C／D；D触发立即结算。这保留双人先手触发补后手、后手触发立即结束的行为。财富最高者中按这一轮更后行动者破同分，不把财富较低的最后玩家误判为胜者；须以不同触发位和多名同财者验证。
- **离席未决**：主动认输／离席后余人继续还是取消，须明确决定；继续时逐项定离席者手牌、货物、道具、扩摊板、在途目标及最高报价的归属，和先手／末轮继承。不能沿用当前“找第一名对手判胜”。意外断线沿现行挂起／30分钟保席合同扩展，不自动等同主动离席政策。

实际影响沿`model/rules/effects/tools/auction`、`validation/lifecycle/view`、正式adapter与事件历史、独立练习／电脑及房间呈现核对。公开道具引用、冻结参赛者、末轮、竞拍人数、结果财富数组和暂停／在线判断都有双人假设；旧双人局及练习存档按原规则继续，须先明确新版本字段和读取边界再写实现。练习新增1～5名电脑时，每名电脑仅读自身合法视图，只有当前行动／决策者推进。阶段进度仍归唯一实施计划，本页不另记完成数。
